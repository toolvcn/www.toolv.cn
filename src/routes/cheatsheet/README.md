# 速查表 · /cheatsheet

> 在线使用：<https://www.toolv.cn/cheatsheet> ・ 数据全部本地处理，不上传、不落库

九张表一页切换，每张表各有独立搜索词（切标签不丢），行尾按钮一键复制。

## 两张专属形态的表

- **MIME 类型**：扩展名 ↔ MIME 双向搜索（输 `png` 或 `image/png` 都命中同一条），按文本与文档 / 图片 / 音频 / 视频 / 字体 / 压缩与包 / 程序与二进制 / Web 与数据格式八类分组；表单那几条没有扩展名，用「—」占位。
- **ASCII 码表**：0-127 全表，十进制 / 十六进制 / 转义写法同屏对照；可打印字符复制字符本身，控制字符复制 `\n` 这类转义写法，没有约定写法的退回 `\xHH`。

## 七张通用速查表

| 表           | 内容                                      | 口径                                                                       |
| ------------ | ----------------------------------------- | -------------------------------------------------------------------------- |
| 常见端口     | 端口 / 服务 / 协议 / 说明，68 条          | IANA well-known 与 registered 端口 + 开发运维常遇的几个                    |
| HTTP 请求头  | 请求头 / 说明 / 示例，60 条               | RFC 9110 / 9111 的请求字段 + CORS / WebSocket / 反代 / 前端的常见非标准头  |
| User-Agent   | UA 片段 / 归属 / 含义，70 条              | 按片段拆开读：浏览器、渲染引擎、系统、设备、爬虫与命令行工具               |
| 特殊符号     | 符号 / 名称 / Unicode / HTML 实体，110 条 | 数学、箭头、货币、引号、键盘符号；有具名实体写具名，没有就给十进制数字引用 |
| Android 权限 | 权限 / 保护级别 / 说明，65 条             | 保护级别按官方四档：普通 / 危险 / 签名 / 特殊                              |

## 参数在哪调

没有 `config.ts`——八张表的数据与展示信息全是静态常量，直接写在 `core/<topic>.ts`（`ports.ts` / `http-headers.ts` / `user-agents.ts` / `symbols.ts` / `android-permissions.ts` / `calling-codes.ts` / `dynasties.ts` / `mime.ts` / `ascii.ts`），七张通用表的注册与顺序在 `core/tables.ts`。改一张表的内容或加表，动数据模块 + `tables.ts` 注册一处即可。

## 档位

L2。编排在 `core/store.svelte.ts`（当前标签、两张老表与七张通用表各自的搜索词，切标签不丢）；通用渲染组件 `ui/ReferenceTable.svelte` 共用一份，两张老表各自有 `ui/MimeTable.svelte` / `ui/AsciiTable.svelte`，标签条与容器在 `ui/Workspace.svelte`，重复样式收进 `ui/styles.ts`。无服务端、无跨工具共享层。

## 实现口径

- 两张老表不套通用表：MIME 的扩展名徽章 + 双向搜索、ASCII 的字符预览块 + 转义写法各有长处，硬套进通用表会把两边都磨平，所以各自保留组件。
- 七张新表共用一份渲染（`ui/ReferenceTable.svelte`）+ 七个纯数据模块（`core/<topic>.ts`），注册在 `core/tables.ts`——加一张表只改数据与注册表一处。
- 行是字符串数组而不是对象：静态短文本用元组写起来一眼能对齐，加一行不会带一堆键名。
- 搜索是 AND 口径：空格分隔的多个关键词全部命中才算（`tcp redis` 能直接定位到 6379）；只影响渲染，不动源数据。
- 窄屏交给横向滚动：速查表的价值在横向对照，表给 `min-w-[30rem]` 下限，放不下整块滚，不拆成「一列一卡片」；表头 `sticky` 钉住，滚长表时列名一直可见。

## 数据口径

- **端口**：只收「填配置、排查占用、写防火墙规则」时会查的；服务端 / 客户端成对的（如 67 / 68）分开列。
- **User-Agent**：UA 能任意伪造，这表是**读懂别人发来的串**用的（排查兼容、认爬虫），不是拿来判断人；`Windows NT 10.0` 同时对应 Windows 10 与 11，说明里点明「分不出来」。
- **特殊符号**：没有 HTML5 具名实体的符号给十进制数字引用（`&#8594;` 永远有效），不留「无」占位——能直接复制走的写法比「这里没有」有用。
- **世界区号**：`+1` 是 NANP 主区，加勒比各分区单独列（`+1 242` 这类）；科索沃用 `XK`（用户自定义码，无正式 ISO 两字母码）。
- **历史朝代**：夏商标「约」；西汉起算写「前 202」（此前四年楚汉相争）、清写「1636 – 1912」（1636 改国号大清，1912 退位）。

## 已知取舍 / 暂不支持

- 不收 Bootstrap 字体图标表：Bootstrap 3 的 Glyphicons 已废弃十年，整表抄进来只是给搜索引擎看，与本页「查了就能用」不符。
- 不做 MIME 全表：只收常见类型，`.bz2` 之类冷门扩展名不收（要全表看 IANA 的 media-types 注册表）。
- 不做码表以外的进制转换：那是 `/radix-converter` 的事。
- 不做账号级收藏 / 笔记：速查是「查完即走」，不需要登录与云同步。

## 验证过什么

- 单测在 `core/*.test.ts`（server project）：`reference-tables.test.ts` 查七张表的结构完整性（列数、空单元格、第一列不重复、规模下限）、每张表的锚点条目（3306 = MySQL、`+86` = 中国、秦 = 前 221 – 前 206、`⌘` 的数字引用）、筛选口径（空词返回全部、大小写不敏感、多词 AND、无结果返回空数组、不动源数据）；`mime.test.ts` / `ascii.test.ts` 覆盖两张老表。
- 浏览器实测：九张标签在 375 与 1280 下无横向溢出、axe 0 violations、表格横向滚动与表头钉住正常、搜索能筛出目标行。
