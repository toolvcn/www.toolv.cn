# 正则表达式测试 · /regex

> 在线使用：<https://www.toolv.cn/regex> ・ 数据全部本地处理，不上传、不落库

- **输入即着色**：透明 textarea 叠在镜像高亮层上，边打字边标出匹配，蓝 / 琥珀交替打底，相邻匹配一眼分得开；分词 `<span>` 上色，不用 `{@html}`
- **一条正则栏**：`/表达式/修饰符` 一体输入条，斜杠已经画好，非法正则整条转红并给出原因；带一键清空按钮
- **六个修饰符开关**：g / i / m / s / u / y 按钮切换，悬浮有中文说明；关掉全局立刻只留第一个匹配
- **中央工作区五个标签**：测试文本 / 匹配详情 / 文本替换 / 代码生成 / 正则图解，一次只占一块地
  - **测试文本**：边打字边高亮的编辑区，实时报匹配数；矮视口下也有最小高度（栅格行下限 16rem + 编辑区下限 8rem），不会被压成一条线
  - **匹配详情**：一行一个匹配（序号 / 文本 / 位置 / 复制），带捕获组的行点箭头展开，也可以一键全部展开；编号组 + 命名组都展示，未参与匹配的组明确标「未参与」
  - **文本替换**：输入替换串（`$1` / `$<name>` / `$&` / `$` /` $'`），整段结果实时输出并统计替换处数，可一键复制
  - **代码生成**：JavaScript / TypeScript / Python / PHP / Java / Go / Ruby / C 八种语言示例，每种都含「构造正则 + 匹配 + 替换」，修饰符按各语言写法映射（如 Python 的 `re.I`、Java 的 `Pattern.MULTILINE`、Go 的内联 `(?i)`），复制即用
  - **正则图解**：把表达式解析成树状图，捕获 / 环视组按色分盒、量词右上角标 `×n`，递归渲染可随表达式实时变化；暂不支持的写法（内联修饰符 / 原子组等）给出原因
- **常用正则表达式在最左侧一栏**：联系方式 / 网络与地址 / 时间与数字 / 开发常用 / 文本处理五组共 46 条，点一下自动填入正则栏；需要特定修饰符的（如行首空白、强密码）会一并带上，说明里写清它的边界；当前正则与某条一致时高亮标出
- **调好的表达式可以存本地**：面板顶部填名称（留空就用表达式本体），勾不勾「同时保存当前测试文本」决定这条配置要不要连测试文本一起存，然后点「保存」，当前 `/表达式/修饰符` 存进 localStorage，刷新后还在；存下来的排在常用正则**最前面**一组「我的保存」，**存了测试文本的条目带文档图标标记**，点了把表达式与修饰符填回并即时重算匹配结果 —— 测试文本为空或还没改过（仍是首屏示例）时连那段文本一起还原，**已经改过则先弹确认再决定覆盖还是保留**；**没存文本的（含旧本地配置）只换表达式、保留当前测试文本**；右侧 × 删除前有确认弹窗。最多 50 条，表达式为空 / 不合法 / 已存过时不给存（按钮置灰并说明原因）
- **正则速查表在最右侧一栏**：字符类 / 锚点与边界 / 量词 / 分组与引用 / 断言 / 修饰符 / 转义与替换七组共 57 条（**组标题带条数**），**一行两条**（条目内部竖排：token 一行、说明一行 —— 右栏窄，横排时说明只剩三四个字）；语法条目点一下插到正则栏光标处（占位写法插可直接用的空壳，如 `(?:)`），修饰符条目点一下直接开关（`d` / `v` 也在里头）
- **复制随手可用**：正则栏一键复制 `/表达式/修饰符`，匹配详情一键复制全部匹配（一行一个），单条也能单独复制
- **有界执行**：零宽匹配自动推进不挂死；命中 1000 个即停并明确标注「已达上限」，渲染量与匹配数同级
- **SSR 首屏有货**：默认示例（日期 + 编号捕获组）构建期就带 3 个匹配，HTML 打开即可读

## 参数在哪调

可调参数在根层 `config.ts`：

- 默认示例：`EXAMPLE_PATTERN = '(\d{4})-(\d{2})-(\d{2})'`、`EXAMPLE_INPUT`（日期测试文本）、`EXAMPLE_FLAGS = 'g'`
- 执行上限：`MAX_MATCHES = 1000`（命中即停并标注「已达上限」）
- 本地保存：`SAVED_STORAGE_KEY = 'toolv:regex-saved'`、`MAX_SAVED = 50`、`MAX_SAVED_NAME = 40`、`SAVED_WITH_INPUT_DEFAULT = true`（保存表单「同时保存测试文本」复选框默认勾上）

常用正则 `PRESET_GROUPS`、速查表 `CHEAT_GROUPS`、flag 元数据 `FLAG_OPTIONS` 与类型都在 `core/types.ts`。

## 档位

**L2**（+page.svelte + config.ts + core/ 纯函数 + ui/ 面板）：`core/regex.ts`（匹配执行 / 防死循环 / 限量截断 / 高亮分词）+ `core/replace.ts`（替换）+ `core/codegen.ts`（8 语言代码生成）+ `core/parse.ts`（正则 → AST 递归下降解析器，图解用）+ `core/saved.ts`（序列化 / 校验）+ `core/store.svelte.ts` + `core/types.ts`。代码生成标签页复用全站共用的 `$lib/components/CodegenTab`（与 http 请求调试共用）。

## 实现口径

- **零宽匹配自动推进**：匹配位置不前进时强制 +1，避免死循环卡死；匹配数到 `MAX_MATCHES` 即截断并标 `truncated`，渲染量与匹配数同级
- **高亮不走 `{@html}`**：把文本切成「匹配 / 非匹配」token，交替配色，纯 `<span>` 上色，复制拿的是原始文本
- **修饰符按语言映射生成代码**：`codegen.ts` 把 g/i/m/s/u/y 翻译成各语言写法（Python `re.I`、Java `Pattern.MULTILINE`、Go 内联 `(?i)` 等），不是简单字符串拼接
- **本地保存的边界判定**：`input !== undefined` 区分「存了空文本」与「没存文本」——空字符串也是有意义现场，不能用真假值判断；已存文本的条目点开还原时，测试文本若被改过先弹确认再决定覆盖还是保留
- **图解解析器独立**：`parse.ts` 把表达式递归下降解析成 AST，内联修饰符 / 原子组等暂不支持的写法给原因而非崩溃

## 刻意不统一

- **删本地保存 / 覆盖测试文本有确认弹窗**：与 docker / git / linux「只复制文本、不做二次确认」不同 —— 这里删的是用户本机数据、覆盖可能丢现场，确认弹窗拦得住真实后果，故保留（linux 复制的是命令文本，确认拦不住任何东西）

## 已知取舍 / 暂不支持

- **不校验业务正确性**：常用正则只给形状（如身份证不校验校验位、银行卡不校验 Luhn、邮箱只按常见形态），边界写在每条 note 里
- **图解不支持全部写法**：内联修饰符（`(?i:…)`）、原子组 `(?>…)`、占有优先量词 `*+` 等给原因跳过，不强行画图
- **代码生成是片段不是工程**：每种语言给「构造 + 匹配 + 替换」最小可运行示例，不含异常处理 / 完整文件骨架
- **替换串只支持 JS 风格 `$1` / `$<name>`**：各语言原生替换语法差异大，这里统一用浏览器正则的替换占位符

## 验证过什么

- `core/regex.test.ts`：零宽推进 / 限量截断 / 捕获组（编号 + 命名 + 未参与）/ 高亮分词交替配色
- `core/replace.test.ts`：`$1` / `$<name>` / `$&` / `$` / `$'` 各占位符
- `core/codegen.test.ts`：8 语言修饰符映射与片段可用性
- `core/parse.test.ts` + `core/parse` 图解：AST 结构、暂不支持写法给原因
- `core/saved.test.ts`：序列化 / 校验（空 / 非法 / 重复不给存）、`input !== undefined` 边界
- 浏览器实测：输入即着色、五标签切换、常用正则点填、本地保存与还原、SSR 首屏带 3 个匹配
