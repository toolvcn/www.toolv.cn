# 子网掩码计算器 · /subnet-calculator

> 在线使用：<https://www.toolv.cn/subnet-calculator> ・ 数据全部本地处理，不上传、不落库

- **三种输入写法都收**：`192.168.1.10/24`、`192.168.1.10/255.255.255.0`、`192.168.1.10 255.255.255.0`；
  完全不给掩码时按 `/24` 算，并在状态条里说明「没写掩码，按 /24 算」—— 猜了就说，不静默
- **网段信息一屏给全**：输入地址、前缀长度、网络地址、广播地址、子网掩码、反掩码（通配符）、
  可用地址范围、可用地址数、地址总数、地址段归属、IP 类别、整数形式、二进制写法；每行都能一键复制
- **子网划分**：把当前网段按选定的目标前缀切成等长小段（最多 64 段），逐段列网络地址 / 可用范围 / 广播地址，
  行尾复制这一段的 CIDR（如 `192.168.1.64/26`）
- **两种界面上的提示各司其职**：状态条说结论（归属、可用数、切了几段），输入框只在地址非法时描红
- **失败给中文**：段数不对、某段超 255、前缀超 /32、点分掩码不连续、一次切出超过 64 段，都直接说清是哪一步不对
- **整页预渲染**：示例、两块面板与空态都在 HTML 里，首屏可读，利于 SEO

## 参数在哪调

**没有 `config.ts`**：业务参数只有默认输入（`DEFAULT_INPUT`）、默认前缀（`DEFAULT_PREFIX`）、
示例清单（`CIDR_EXAMPLES`）与一次最多列多少段（`MAX_SUBNETS`），都在 `core/subnet.ts` ——
没到「同一个数散在 `core/` 与 `ui/` 两边」或「被三处引用」的门槛，按 `STRUCTURE §2 B` 就地放着。

## 档位

**L1**（`+page.svelte` + `core/store.svelte.ts`），但拆了 `ui/` 的两块面板（`InfoPanel` / `SplitPanel`）——
一个工作区里两块内容各自要独立滚动与状态条，摊在一个文件里会到 300 行且互不相干。
没有 `ui/styles.ts`（没有同一串样式出现两处的地方，面板骨架与表格样式都直接用 `$lib/ui/styles` 与 Tailwind）。

## 实现口径

- **位运算一律 `>>> 0`**：JS 的位运算跑在 int32 上，`(a << 24) | …` 的结果可能变成负数 ——
  `255.255.255.255` 这类地址只要漏一处就会显示成 `-1`（单测里专门钉了这条）
- **/31 与 /32 是特例**：`/31` 是两个地址都能用的点对点网段（RFC 3021），`/32` 是单个主机地址，
  都不能套「地址总数 − 2」，状态条也会把这句话说明白
- **地址段归属按「更具体的先命中」**：特殊段表按前缀从长到短排（受限广播 `/32` 排在保留段 `240/4` 前面），
  否则 `255.255.255.255` 会先被 `240/4` 吃掉
- **划分的上下界**：一次最多列 `MAX_SUBNETS = 64` 段（目标前缀最多往后 6 位），
  超出时报错并提示把目标前缀调小 —— 不把 1024 行表格甩给浏览器
- **用户手选的目标前缀会做有效性校验**：选的档位比当前前缀还短（换输入之后可能出现）就自动退回默认档，
  界面不会出现「下拉显示 /28、结果却是 /26」这种不一致
- **输入非法时两个面板一起回到空态**：不保留上一次的结果，避免「结果还在、但它不是当前输入算的」
- **控件一律在工具条，卡片只出结果**：切分目标前缀没有放进「子网划分」卡片的标题行 ——
  标题行里的下拉是浮层，会依次踩到两个坑（卡片的 `overflow-hidden` 把菜单裁掉、表格 `sticky` 表头的
  `z-10` 又把菜单压住）。这与 `/unit-converter` 的口径一致

## 已知取舍 / 暂不支持

- **不做 IPv6**：IPv6 的子网概念（/64 起步、没有广播地址、地址写法与压缩规则）完全是另一套，
  与 IPv4 挤在一页只会两边都讲不清；留给单独一页
- **不做「两个 IP 是否同一网段」的对比**：本轮先做「一个网段算清楚 + 能切分」，
  对比是另一个入口（要再加一行输入与一组结论），需要时再单独提
- **不做 VLSM / 变长掩码划分**：那是个带约束求解的规划工具（按每个子网要多少台反推掩码），
  与「等长切分」不是一个量级的功能
- **不查 IP 归属地 / ASN**：要联网查库，与「数据本地处理」冲突

## 验证过什么

- 单测 31 条在 `core/subnet.test.ts`（vitest 的 server project）：四段解析与往返、边界地址的无符号性、
  CIDR 三种写法与各类非法输入的中文报错、`maskOf` 与 `prefixOfMask` 互逆、
  手算锚点（`192.168.1.10/24` → `.0`/`.255`/254 台、`172.16.5.9/21` → `172.16.0.0 – 172.16.7.255`、
  `0.0.0.0/0` → 掩码 0 且可用 4294967294）、/31 与 /32 特例、特殊地址段归属（回环 / 链路本地 /
  运营商级 NAT / 组播 / 保留 / 受限广播 / 公网）、划分的步长与边界、以及 store 的派生状态
  （非法输入回空态、assumed 提示、手选前缀失效后回退、示例逐条可解析）
- 浏览器实测：375 / 1280 下两块面板无横向溢出、axe 0 violations、表格横向滚动、示例与复制可用
