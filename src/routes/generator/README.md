# 随机生成器 · /generator

> 在线使用：<https://www.toolv.cn/generator> ・ 数据全部本地处理，不上传、不落库

- **UUID v4 批量**：1-10000 条，可选大写、去连字符（后处理不影响随机性）；底层走 `crypto.randomUUID`。
- **强随机密码**：长度 4-64、数量 1-10000，大小写 / 数字 / 符号四类字符池自由勾选，可排除易混淆字符（`0Oo1lI|`）；支持追加自定义字符集（自动去重）；实时估算单条熵（bit）并分五档（极弱 / 弱 / 中等 / 强 / 极强）；勾选的每类保底出现一次，整体洗牌。
- **随机数**：`[min, max]` 闭区间取 1-10000 个，支持 0-6 位小数、整数去重、升序排列；范围装不下这么多不重复的数会明确报错。
- **占位假文**：拉丁（Lorem Ipsum 经典开头起手）与中文两种语言，按句子或段落计数（1-10000），段落自动换行成块。
- **数量边界两层**：`COUNT_WARN` = 500 以上先弹一次 confirm（生成是同步的，卡的是主线程）；`COUNT_MAX` = 10000 是硬上限，超过即判非法、生成按钮直接禁用 —— 二次确认挡手滑，硬上限挡「点掉 confirm 再填 10 万」。
- **常用数量一键填**：数量输入框右侧四个 chip（10 / 50 / 100 / 500，见 `QUICK_COUNTS`）。
- **复制**：逐项复制 / 一键复制全部。
- **SSR 稳定**：结果一律点「生成」才出，避免 hydration 前后随机值不一致。

## 参数在哪调

四个标签的默认值与上下限、假文的档位区间、强度五档切界都在根目录 `config.ts`（`COUNT_MAX` / `COUNT_WARN` / `QUICK_COUNTS` / `PASS_LENGTH_*` / `NUM_VALUE_*` / `DECIMALS_*` / `MAX_*_COUNT` / `LATIN_WORDS_PER_SENTENCE` / `ZH_CHARS_PER_SENTENCE` / `SENTENCES_PER_PARAGRAPH` / `STRENGTH_LEVELS`）。界面上那几个区间提示（「长度（4-64）」之类）由它拼出来，改上限不会再漏改提示句。字符集与假文词表**不在**里面 —— 那是要产出什么，不是行为参数，留在 `core/types.ts`。

## 档位

**L2**：`config.ts`（参数）+ `core/`（`random.ts` 纯函数 + `types.ts` 类型与语料 + `store.svelte.ts` 编排）+ `ui/`（`Workspace` 与各标签面板）。随机源可注入（`RandomSource`），单测用确定性序列断言。

## 实现口径

- **随机源统一 `crypto.getRandomValues`**；区间取整一律「拒绝采样」—— 先消掉 `2^32` 除以区间的余数再取模，杜绝模偏差；小数用 32 位随机字均匀映射到 `[min, max)` 后按位数 `toFixed`。
- **密码**：勾选的每类 + 自定义字符池各保底出现一次，其余从整体池随机填满，再 Fisher-Yates 洗牌，保底字符不堆在开头。
- **熵估算 = 长度 × log2(池大小)**，位数上取整；强度按熵分五档（阈值在 `STRENGTH_LEVELS`）。
- **生成是同步的会卡主线程**：所以数量超 `COUNT_WARN` 先 confirm、超 `COUNT_MAX` 直接禁用按钮，而不是让页面白屏几秒。
- **结果点「生成」才出**：SSR 预渲染保持稳定，避免服务端 / 客户端各算一遍导致 hydration 不一致。

## 已知取舍 / 暂不支持

- **不连任何外部随机服务**：纯浏览器 `crypto`，不上传、不依赖服务端。
- **小数模式下去重无意义**：整数去重开关自动锁定并说明（小数值域连续、去重无定义）。
- **不做密码学以外的花样**：不保证指定首位、不含词典词、不校验「是否在常见密码库里」；强度档位只是熵参考，不是爆破抗性担保。
- **假文只占位、不通顺**：中文假文随机组字拼句，视觉上像正文即可，不保证语法与语义。

## 验证过什么

- `core/random.test.ts`：UUID 格式与后处理、密码各类保底出现 / 自定义集去重 / 洗牌、随机数无偏与小数位、假文句子 / 段落长度落在档位区间。
- 浏览器实测：375 / 1280 无横向溢出，axe 0 violations。
