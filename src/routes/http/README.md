# HTTP 请求调试 · /http

> 在线使用：<https://www.toolv.cn/http> ・ 默认浏览器直发、数据本地处理；可开启「服务器代发」经 Cloudflare 转发请求以绕开 CORS 并测速

面向开发者的在线 HTTP 调试工具，版式对齐 Hoppscotch：顶部一条请求栏 → 请求配置四个标签（参数 / 授权 / 请求头 / 请求体）→ 响应面板（结果置顶 + 响应体 / 响应头 / 状态码）。支持与浏览器 DevTools 的复制格式（cURL / PowerShell / fetch）互转、8 种语言代码生成、参数预设本地持久化；可选的「服务器代发」让调试不再受浏览器 CORS 限制。

**定位**：以「单次请求」为核心 —— 把一次请求发得准、看得清。**刻意不做**集合 / 请求历史 / 环境变量这类组织层功能（那是完整 API 客户端的活），也不做团队协作与云同步（与「数据本地处理」冲突）。

## 界面布局

桌面端两栏：**左栏是工作区导航 + 参数预设**，主区是当前工作区的内容。

```
┌ 左栏 16rem ────┬ 主区 ─────────────────────────────────────────────┐
│ [请求调试]      │ ① 请求条（两行）                                 │
│ [导入 / 导出]   │    [POST▾][ https://…     📋 ][示例][▶ 发送]     │
│ [代码生成]      │    [超时 10s▾][○ 服务器代发]          [清空]      │
├────────────────┤ ② 请求构造   ⇱  [参数][授权][请求头][请求体]      │
│ 参数预设        │ ③ 响应       ⇱  200 OK · 128 ms · 1.2 KB         │
│ 名称   [保存]   │                          [复制为▾] [⧉ 左右|上下] │
│ ▸ 预设A         │    [响应体][响应头][状态码]  [美化][原始][预览]  │
│ ▸ 预设B         │                                                  │
└────────────────┴──────────────────────────────────────────────────┘
```

**三个工作区标签竖着排在左栏、预设上方**，不再横在主区顶上：横排那条标签栏要在主区占掉一整条
48px 的高度，而左栏只有 16rem、竖着排正好装得下 —— 主区因此多出整条标签栏的高度给请求与响应。
当前是哪个工作区由左栏的选中态表达，主区不再有标签栏。

**「请求调试」的内容直接落在主区上，不再套一层外壳卡片**：它自己就是三张卡（请求条 / 请求构造 / 响应），
外面再套一层就是白卡套白卡，而且会把它的卡片边距推得比左栏多出一层 —— 现在两者的左边线同在 ToolShell
的 `p-4` 处，对齐。另外两个工作区的内容本来不是卡片（靠外层卡片成形），才由外壳卡片接住。
主区那层的 `heading` 仍保留（渲染成屏幕外标题），所以区域的读屏名字不丢。

移动端左栏是整页宽，竖排反而白占纵向高度，所以那里退回一排横排。
**小屏的堆叠顺序是「工作区标签 → 主区 → 参数预设」**，同一份 DOM 靠 `lg` 的显式栅格定位换位置：
手机上先把「输入 URL + 发送」这条主路径给人看到，而不是让预设货架夹在标签与请求条之间
（预设是次要面板，`PresetPanel` 在移动端还有 `max-lg:max-h-56` 封顶）。`lg` 上标签回左栏顶部、
预设回左栏下方、主区占右栏整高 —— 所以 DOM 按小屏顺序写，`lg` 那层不是「左栏 + 主区」两个格子而是四个。

小屏还要 `content-start`：栅格的 `align-content` 默认是 `stretch`，会把「内容没占满的那部分高度」
分摊给 `auto` 行 —— 内容短的工作区（「代码生成」）里标签卡那一行会被拉高（实测 54px → 92px），
看上去就是「三个工作区选择下面多出一块白」。宽屏有显式行模板（`auto + 1fr`）本来就填满，用不上。

「请求调试」这一屏自上而下只有一条主路径（小屏滚动时请求条吸在导航栏下）：

几处刻意的取舍：

- **结果面给浅灰底**（响应面板的「响应体」与「响应头」两块，`ui/styles.ts` 的 `RESULT_SURFACE`）。
  响应体、上方的结果行与标签行、左边的请求构造原先全在同一片白底上 —— 一整屏 JSON 浮在白卡里，
  看不出「结果区从哪儿开始」；铺上 `gray-100` 之后与白底的请求编辑区一眼分开
  （**请求 = 白底编辑区，响应 = 浅灰结果面**）。第一版用的是 `gray-50`，实测太淡等于没铺，所以升了一档。
  「状态码」那块**刻意不铺**：它是参考手册不是结果正文，而且里面 1xx 的徽章本身就是 `gray-100`，会糊在一起。
  底色挂在容器上而不是 `<pre>` 上，所以空态 / 错误态 / HTML 预览切来切去时这块面不会忽白忽灰；
  共享的 `OUTPUT_PRE` **没动**（json-formatter 也用它，那边输出区本身就是整张卡片）

- **状态码速查从常驻右栏改成响应面板的第三个标签**。它查一次就走，却一直占着 18rem，把请求 / 响应挤到不足 700px —— 最抢眼的位置给了最低频的内容。搬进响应区后位置也更合理：它是「这个状态码什么意思」的参考手册，问的正是刚收到响应的那一刻。
- **结果信息只在响应面板标题行出现一次**（状态码 / 耗时 / 大小 / 代发测速），既是结果摘要也是读屏播报的活区。原先标题行挂徽章、单独一条测速条、底栏再写一遍，同一个结果要看三处。
- **请求与响应可切上下 / 左右**。上下时响应拿到整宽；左右时两边同时可见，改请求头不用来回滚。
- **两个面板各自可收起、可全屏**（标题行右侧那两枚图标）。收起请求构造 → 高度全给响应；收起响应 → 高度全给
  请求构造。收起响应**不等于看不见结果** —— 状态码 / 耗时 / 大小就在它的标题行里；收起时点标签会自动展开，
  所以「收起」不会把人锁在外面。
  **全屏走浏览器原生 API**（`requestFullscreen`，与 `/clock` 的「本页全屏」同一套；按钮是共享件
  `$lib/components/FullscreenButton`）：Esc 退出、焦点与键盘可达性都由浏览器负责 —— 自绘 `fixed` 遮罩
  就得自己补焦点陷阱 / inert / 滚动锁定，那才是这个功能全部的复杂度。被拒（沙箱 / 权限策略）时提示按 F11。
  全屏时面板换成 `h-dvh`（**不能用 `h-full`**：全屏元素的父级高度是 `auto`），小屏的高度封顶一并去掉。
  **一处已知**：手机全屏看「状态码」那一页时列表仍按 `max-lg:max-h-[60vh]` 封顶 —— 那个封顶在非全屏的小屏下
  是必需的，而它在 `StatusTab` 内部、不随全屏切换（要修得给它加个 prop）

## 请求调试

### 请求条

- **方法**：GET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS
- **小屏版式**：排三行 —— ① `[方法 + URL]`（独占一行，URL 要宽）；② `超时 ▾ … 示例 ▾ 发送`
  （超时在左、后两个贴右）；③ `⬤ 浏览器直发 … 清空`（开关在左、清空贴右）。
  实现是窄屏把两个行容器 `max-md:contents` 溶解、5 个控件组回到工具条同一层换行流，再用
  `max-md:order-*` 排序；第一组用 `basis-full` 独占一行（它带 `flex-1`，`flex-basis: 0%`
  会盖过 `w-full`），「超时」下拉窄屏也补到 `h-9` 与同行控件齐平（同一行不混高度）。
  挤在一行会把 URL 压到 200px 上下、还得跟粘贴按钮抢位置；退成竖排 `flex-col` 又会让按钮
  变成横贯整行的蓝条（360px 下 302px 宽）。宽屏这些前缀全部失效，回到「主行 + 次行」两行
- **URL**：可省略协议，自动补 `https://`；格式非法在发送前拦截并提示；**框内按 `Enter` 直接发送**
- **从剪贴板粘贴**：URL 框**右端内侧**的图标按钮直接读剪贴板，按同一套规则识别（cURL bash / cmd、
  PowerShell、fetch、或一条裸 URL）。识别到请求就填整套表单并切回本标签；只识别出一条链接时**只填 URL**，
  方法 / 请求头 / 请求体不动（那是当前表单里别的东西，不该被一条链接冲掉）。读不到剪贴板
  （未授权 / 非安全上下文）会提示改手动 `Ctrl / Cmd + V`
- **快捷键**：URL 输入框内按 `Enter` 直接发送（等于点「发送」/ 请求中则为「取消」）；
  `Ctrl / Cmd + Enter` 在页面任意位置都能发送。请求头 / 请求体是多行文本，那里 `Enter` 仍是换行。
  中文输入法用回车确认候选词时不会误发（`isComposing` 守卫），URL 框带 `aria-keyshortcuts` 与
  `enterkeyhint="send"`（移动端键盘那颗键显示为「发送」）
- **超时**：5 / 10 / 30 / 60 秒四档，超时自动中断。**服务器代发最高 10 秒** —— 所选档位超过 10 秒时，
  代发按 10 秒算：发送方式那行会写明「服务器代发 · 超时按 10 秒算」，超时提示也会带上「（服务器代发上限 10 秒）」；
  下拉里选的档位**不会被改写**（关掉代发就回到原来的秒数）。浏览器直发不受这条限制
- **发送方式**：浏览器直发（默认）/ 服务器代发（见下文）
- **示例**：一个菜单，7 条各演示一件事的请求 —— 最简 GET / 查询参数 / JSON 请求体 / 表单字段 / Bearer 认证 /
  404 状态码 / 延迟 3 秒。点一条就填进表单，并把「请求构造」翻到对应的标签页（参数 / 授权 / 请求体）并展开，
  免得演示的内容藏在收起的面板里。数据在 `config.ts` 的 `REQUEST_EXAMPLES`；
  **没写认证与超时的示例不会动你当前的值**（与预设相反：预设存的是整条请求，缺什么就是什么）
- **清空**：把 URL / 请求头 / 请求体 / 参数行清掉，**默认保留认证信息**（token 是身份，不该跟着表单一起清）

### 参数（查询参数表）

- 键值表格：每行「键 / 值 / 勾选 / 删除」，**取消勾选的行留在表里但不发送**
- **与 URL 双向同步**：在表里改，URL 跟着变；直接改 URL，表也跟着变（同步逻辑在 `core/params.ts`，两个方向都用 `URLSearchParams`，口径自洽）
- `#fragment` 原样保留；重复键（`?a=1&a=2`）保留顺序

### 授权

- **无认证 / Bearer Token / Basic Auth / API Key**（API Key 可选放请求头或查询参数）
- 面板上常驻一条「这条请求实际会附加什么」的预览，**不回显密钥明文**，只写形状
- **手写的同名请求头优先于注入值**：在「请求头」里显式写了 `Authorization`，就以你写的那条为准
- **不做 OAuth 2.0**：授权码流程要一个回调端点、客户端密钥也没有地方托管，纯前端做不了完整流程
- 存成预设时认证信息会一起写进浏览器本地存储（见「隐私说明」）

### 请求头

- 多行输入框，每行一条「名称: 值」，`#` 开头的行为注释、空名称不发送；面板显示「N 条生效」
- 保持文本形态（而不是改成键值表）：粘贴一大坨请求头是这里最常见的用法，文本比逐格填快；
  参数表之所以是表格，是因为它要与 URL 双向同步
- **默认是空的**，打开页面不会自动代入任何本机请求头 —— 发送时以输入框当前内容为准
- 右上角两个按钮：**本机** → 确认后以本机浏览器会带上那几个头（`User-Agent` / `Accept` / `Accept-Language` /
  `Accept-Encoding` / `Upgrade-Insecure-Requests`，Chromium 系再补 `Sec-CH-UA` 三项）**整块覆盖**输入框；
  **清空** → 确认后清空全部请求头，回到占位提示。两者取消时输入框内容都不动
- 「本机」那份是底稿不是抓包结果：浏览器不允许 JS 读自己即将发出的头，也改不掉 UA / `Accept-*` 这些
  由它自己接管的头 —— 填进来是给你照着改的

### 请求体

- **类型**：无 / JSON / 纯文本 / 表单（`application/x-www-form-urlencoded`）
- 类型就是 `Content-Type`，两者本是一件事，所以只有一个选择项；选了 JSON 就自动带 `application/json`
- **表单类型用键值表填写**，发送时拼成 `a=1&b=2`；勾掉的行不参与
- JSON 类型提供「格式化」（`JSON.stringify(…, null, 2)`），内容不是合法 JSON 时在说明行提示「仍会原样发送」
- GET / HEAD 不发送请求体，编辑区禁用并说明原因

## 查看响应

- **结果行**：**状态码 + 简略说明**（`404 未找到`）/ 耗时 / 响应大小在响应面板标题行汇总。
  说明取自本地的状态码数据表（`core/status-codes.ts` 的 `statusBrief`），表里没有的码先用服务端 reason phrase、
  再退到分类名（`520` → `5xx 服务器错误`）。**主显示不用服务端那句**：HTTP/2 根本不返回 reason phrase，
  那样就只剩一个光秃秃的 `200`。服务器代发时再补 TTFB 与下载速度，响应体超上限被截断也会写在这里
- **复制为**（标题行右侧的下拉）：**响应体** / **响应头**（每行一条「名称: 值」，可直接粘进请求头输入框），
  以及把**这条请求**复制成 cURL（bash / cmd）/ PowerShell / fetch（浏览器 / Node.js）—— 请求那几项与
  「导入 / 导出」标签共用同一个生成器（`core/request-text.ts`），只是入口不同。
- **响应体**：**美化**（JSON 高亮）/ **原始**（原文）/ **预览**（HTML 用 `sandbox` 的 iframe 渲染，脚本、表单、跳转全被拦掉）。
  非 JSON 的响应点「美化」、非 HTML 的点「预览」，都**弹一条说明**而不是把按钮灰掉 —— 原生 `disabled` 的按钮
  收不到鼠标事件，挂在它上面的 `title` 永远弹不出来，用户只能看到一颗灰按钮、猜「是不是坏了」。
  控件的高亮读的是**实际显示的那一档**，不会出现「上一份响应预览过 HTML、这一份是 JSON，却仍高亮着灰掉的『美化』」
- **行号与行数**：正文左侧常驻**行号槽**（`sticky left-0`，横向滚动看长行时钉住不动、不被拖走），
  标签行右侧给出「共 N 行」—— 不用滚到底也知道这响应多长。行号取自**显示出来的内容**：
  美化视图数的是重排后的行（紧凑 JSON 源文本只有一行，数源文本会得出「1 行」这种没用的答案），
  原始视图数文本本身 —— 口径与生成都在 `core/line-numbers.ts`
- **响应头**：完整键值对列表；跨域直发只暴露少数几个头，需要看全就用服务器代发
- **状态码**：60+ 条速查表，收到响应后切到这个标签会自动滚动定位并短暂高亮
- **全屏**（标题行右侧那枚方形图标，`aria-pressed` 表达状态）：把整块**响应面板**送进浏览器原生全屏，
  结果行与标签行都还在，Esc 或再点一次退出。原理、为什么不用自绘遮罩、以及一处已知限制，
  见上面「界面布局」的取舍那节（请求构造面板那枚是全屏看它自己）
- **一键复制**：复制响应体、复制当前请求的 cURL 命令
- **保存响应到文件**（响应体标签行那枚下载图标）：把**完整**响应体存成文件，文件名按 Content-Type
  猜扩展名、带状态码（`response-200.json`），连发几次不会互相覆盖
- **大响应只截显示、不截数据**：超过 `MAX_BODY_CHARS / MAX_BODY_TOKENS` 时屏幕上只渲染前一截
  （提示条写明截了多少、共多少，并给「仍显示全部」），但复制与保存拿到的始终是**全文** ——
  卡住浏览器的是把几十万个节点铺进 DOM，不是读回几 MB 文本
- **跨域凭证**（请求条第二行「跨域凭证」下拉）：同源才带（默认，与浏览器原生行为一致）/ 都不带 /
  跨域也带。`include` 需要服务端同时返回 `Allow-Credentials` 且 `Allow-Origin` 不能是 `*`，
  否则请求会被浏览器直接拒 —— 这句写在选项说明里；选择随参数预设一起存（旧预设按默认兜底）
- **错误兜底**：CORS 拦截或网络失败给出明确文案 + **两条「把执行搬出浏览器」的路**（两个按钮）：
  复制 cURL 到本机终端跑、复制 fetch 代码粘到「目标站点自己」的控制台里跑（同源，天然没有 CORS，
  也不需要目标服务端配合）。文案里同时提醒：**这类报错不代表请求没发生** —— 不需要预检的请求
  （如 `text/plain` 的 POST）仍会在服务端执行，写操作要自行确认

## 导入 / 导出（与 DevTools、终端、其它工具互转）

导入侧**自动识别格式**（不必先选是哪种），导出侧把当前请求生成成同一批格式：

| 格式                 | 来源                             | 生成的写法                                                                    |
| -------------------- | -------------------------------- | ----------------------------------------------------------------------------- |
| **cURL（bash）**     | DevTools `Copy as cURL (bash)`   | 单引号 + `\` 续行                                                             |
| **cURL（cmd）**      | DevTools `Copy as cURL (cmd)`    | 双引号 + `^` 续行，内层 `"` 转义为 `\"`                                       |
| **PowerShell**       | DevTools `Copy as PowerShell`    | `Invoke-WebRequest`，值用单引号字面量                                         |
| **fetch（浏览器）**  | DevTools `Copy as fetch`         | 与 DevTools 一致：`JSON.stringify` 出来带双引号键，含 `mode` 与 `credentials` |
| **fetch（Node.js）** | DevTools `Copy as Node.js fetch` | 同上，去掉浏览器专属的 `mode` / `credentials`                                 |

解析是**宽容**的，因为用户从好几个地方复制过来：引号单双都收、续行 `\` / `^` / 反引号都收、
`curl` 与 `curl.exe` 都收、`Invoke-WebRequest` 的哈希表里被空格拆开也认。
cURL 那部分支持 `-X / -H / -d* / --data-urlencode / -u / -b / -A`，`-s -i -L -k` 等展示性 flag 自动忽略。

- **URL 框右端那个图标按钮是这条链路的快路径**：读剪贴板 → 同一套识别 → 直接填表，不用先切到本标签。
  两边共用一个解析器，只是入口不同（按钮在 `store.pasteFromClipboard()`，这里是文本域 + 「解析到表单」）
- 解析出的 URL 会同步进参数表；表单类型的正文会拆进表单键值表
- **认证不会被粘贴覆盖**：文本里带了 `Authorization` 就照放进请求头（手写的优先于注入），但不去动「授权」标签里配的东西
- 解析成功自动切回「请求调试」标签并弹出提示，失败给出具体原因（例如「fetch 用了变量」会提示改用 cURL）

参考依据（2026-09-20 查 `devtools-frontend` 的 `NetworkLogView.ts`）：`Copy as cURL (cmd)` 与 bash 共用
一个生成器、只在 Windows 出现；`Copy as PowerShell` 是**独立**生成器，所以它出的是 PowerShell 原生写法
而不是 cURL 的第三种方言；两种 fetch 都是先构造对象再 `JSON.stringify(options, null, 2)`。

## 代码生成

- 按当前请求实时生成 8 种语言请求代码：JavaScript / TypeScript（fetch）、Python（requests）、Go（net/http）、Java（HttpClient）、PHP（cURL）、C#（HttpClient）、PowerShell（Invoke-RestMethod）
- 生成的口径与发送完全一致（参数表、表单表、认证注入都在 `toCurlForm()` 里算好），所以生成出来的代码能直接跑
- 切换语言即时重算，一键复制

**与「导入 / 导出」的边界**：这里是**写进代码工程**的代码（干净、只留必要字段）；那边是**在工具之间搬运**的
DevTools 复制格式（保留 `mode` / `credentials` 这类「录制痕迹」）。所以两边的 fetch 输出**有意不同**，
不是重复实现 —— 改一处不影响另一处，各自的目的是独立的。

## 参数预设（左栏）

- 填好整套请求参数后填名称点「保存」入库，列表本地持久化（localStorage）
- **一条预设存的是整条请求**：方法 / URL / 请求头 / 请求体 / 超时 + **参数行 + 认证配置**
- 点条目整组回填表单；条目可单独删除
- 导出为 JSON 文件、从 JSON 文件导入合并；**旧版本导出的文件仍能读进来**（参数行与认证是后加的字段，缺失时回落到从 URL 解析 / 按「无认证」处理）

## 服务器代发（技术说明）

开启「服务器代发」后，浏览器把请求参数 POST 到本站的 Cloudflare Pages Function（`/http/proxy`）代为转发：

- **完整转发**：状态码 / 响应头 / 响应体原样回传（响应体 base64 承载防二进制乱码），响应体上限 1MB，超出自动截断并标记
- **测速指标**：TTFB（到响应头的耗时）、总耗时、下载耗时、下载速度（B/s）
- **超时**：**上限 10 秒**（`config.ts` 的 `MAX_PROXY_TIMEOUT_MS`）—— 代发用的是本站服务器资源，长挂请求既费资源、也容易被当成免费的慢接口代理，所以封顶。前端先夹一次（`store.effectiveTimeoutMs`）、服务端收到更大的值再夹一次（前端被改也拦得住），客户端与服务端双侧同时中断；**浏览器直发不受这条限制**
- **安全**：代理只放行 http/https；拦截内网网段（10 / 172.16 / 192.168、回环 127、链路本地 169.254、CGNAT）、IPv6 回环 / ULA / 链路本地 / 内嵌 IPv4、`localhost` / `.local` / `.internal` / `.lan` 等保留主机名、云元数据地址（169.254.169.254、metadata.google.internal）——防止代理被当作 SSRF 跳板
- 代理失败（拦截 / 超时 / 目标不可达）会给明确原因文案

## 隐私说明

默认「浏览器直发」：请求完全由你的浏览器发出，工具不上传任何数据。开启「服务器代发」后，请求参数（URL / 头 / 体）会经本站服务器转发，用于绕开 CORS 并测速；这是全站唯一涉及服务端的数据路径，且为手动开启的开关项。

**认证信息与预设都存在浏览器本地**（`localStorage`，键见根目录 `config.ts`）。预设里包含认证配置（token / 密码 / API Key），共用电脑上请留意；工具页不提供「记住登录」以外的任何服务端存储。

## 已知取舍 / 暂不支持

- **multipart 表单 / 文件上传**：需要同时改 8 种语言的代码生成（JDK 的 HttpClient 根本没有 multipart 支持）、预设格式与 cURL 的 `-F`，单独一轮做
- **图片 / 二进制响应预览**：预览只覆盖 HTML；图片要先留住原始字节，涉及发送路径改造（现在 `res.text()` 与代发的 base64 解码都会丢掉二进制）
- **OAuth 2.0 授权**、**Cookie Jar 自动管理**（跨域读不到 `Set-Cookie`）、**自定义代理**、**忽略 SSL 证书** —— 浏览器或纯前端做不到
- **跨域读不到响应（CORS）**：这是**浏览器策略**、不是工具缺陷，纯前端无解。三条出路：① 让目标服务端加
  `Access-Control-Allow-Origin`（治本，调自己的接口时）；② **把执行搬出浏览器** —— 本机终端跑 cURL、或用
  Postman 一类桌面工具，界面上给了一键复制；③ 复制 fetch 代码粘到「目标站点自己」的控制台里跑（同源、零配置）。
  ⚠️ 另外：**报这类错不代表请求没发出去** —— 不需要预检的请求（如 `text/plain` 的 POST）在服务端照常执行。
  第三方公共 CORS 代理**不推荐**（请求内容全经第三方）。本工具的「服务器代发」是可选项，也是全站唯一
  经服务器的数据路径，所以默认关闭
- **HAR 文件**、以及**用变量拼出来的 fetch**（Postman 导出的就是 `var requestOptions = {…}; fetch(url, requestOptions)`）——
  这两类不是字面量，解析器会明确报错并提示改用 cURL，不假装能读
- 请求历史 / 环境变量 / 集合 —— 定位上不做（见文首「定位」）

## 分层约定（改这一页前先看这条）

**`toCurlForm()` 是唯一的出口**：它返回**生效后的** URL（含 API Key 查询参数）、请求头（手写 + 认证注入、去重后）、请求体（表单表拼好的正文）。cURL 生成、代码生成、实际发送三条路都读它。

好处是 **`core/curl.ts` 与 `core/codegen.ts` 完全不知道参数表与认证的存在** —— 加这两个功能没有动它们一行，它们的单测也就没被波及。以后再加「生效层」的能力（比如环境变量插值），也应该加在 `store` 的这一层，而不是往下钻。

## 参数在哪调

超时档位（5 / 10 / 30 / 60 秒）与默认值、服务器代发的响应体上限与超时上下限（上限 10 秒）、「示例」菜单那几条请求（`REQUEST_EXAMPLES`）、预设的 localStorage 键都在根目录 `config.ts` —— **加一条示例只改这一处**（说明文案跟数据写在一起）。其中**默认超时 10 秒**同时被三处引用：`core/store.svelte.ts`（表单初值）、`core/presets.ts`（导入 / 恢复时字段缺失的兜底）、`proxy/+server.ts`（收到非法值时的兜底）—— 改一个常量三处同步。

请求与响应的类型、方法 / Content-Type / 认证方式 / 请求体类型的下拉选项**不在**里面：类型与选项在 `core/types.ts`，认证方式选项跟着实现走 `core/auth.ts`。

## 实现口径

- **摘要计算异步 + 竞态编号**：连打只认最后一次发起的，晚到的旧结果直接作废（`store.svelte.ts` 的自增序号）。
- **服务器代发双端夹超时**：`proxy/+server.ts` 与前端 `store.effectiveTimeoutMs` 都夹到 `MAX_PROXY_TIMEOUT_MS` = 10 秒，界面写明的秒数与实际中断时刻一致；浏览器直发不受这条限制（5 / 10 / 30 / 60 秒四档都可选）。
- **响应体渲染上限只卡显示不卡数据**：完整响应始终在（复制 / 保存拿全文），只是默认不一次全铺进 DOM —— 十几 MB 的 JSON 一渲染整页就无响应。
- **参数表与 URL 双向同步**：两个方向都用 `URLSearchParams`，口径自洽；`#fragment` 原样保留、重复键保留顺序。
- **粘贴识别多格式**：cURL bash / cmd、PowerShell、fetch、或一条裸 URL 同一套规则；只识别出链接时**只填 URL**（不冲掉当前表单的方法 / 头 / 体）。
- **「本机」请求头是底稿不是抓包**：浏览器不允许 JS 读自己即将发出的头，填进来是给你照着改的。
- **全屏走原生 `requestFullscreen`**（按钮在共享层 `$lib/components/FullscreenButton`，与 `/clock` 同一套）：Esc 退出、焦点与键盘可达性由浏览器负责，不自己画 `fixed` 遮罩（省掉焦点陷阱 / inert / 滚动锁定）。

## 踩过的坑

- **`-Headers` 的值不能被切坏**：`splitShellTokens` 会去掉引号，而 `@{…}` 里的分隔符 `;` 与值里的 `;`
  （cookie 常见）只能靠引号区分，掉了引号就分不清。修法是让 `-Headers` 这一项走**原文切片**
  （`core/curl.ts` 的 `rawHashtableAfter`，带引号感知的花括号配平），其余参数仍用 token ——
  改插件词法这块别再退回「全部用 token」。
- **用户说的「行号」不是「截断」**：曾把「可选显示行数」理解成「只渲染前 N 行」并做了一版
  （下拉 + config 档位 + `core/line-limit.ts`），被明确纠正「我的意思是可以看响应结果是多少行的；左侧显示行数」
  后整块撤掉。**以后遇到「显示行数」先分清是「左侧行号」还是「只显示前 N 行」** —— 那版即使保留也会撞词
  （一个叫「行数」的截断下拉 + 左侧行号，同一个词两个含义）。
- **响应面板「复制为」菜单仍会被裁（已知未修）**：那个 `Panel` 是 `clip=true`（卡内有通栏 `border-b` 与浅底结果面，
  关掉 `clip` 会让它们露出直角，3 个标签页都要各自补 `rounded-b-xl`，易漏）。面板展开时菜单落在卡内、看不出问题；
  **面板收起（只剩 h-12 标题行）时菜单会被裁得只剩一条**。真要修得让共享 `Dropdown` 支持浮层挂到 body（fixed 定位）。
