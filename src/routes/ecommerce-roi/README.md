# 电商 ROI 计算 · /ecommerce-roi

> 在线使用：<https://www.toolv.cn/ecommerce-roi> ・ 数据全部本地处理，不上传、不落库

## 它解决什么

电商运营嘴里的「ROI」和财务口径的 ROI 不是一回事：后台报的是 ROAS（成交额 ÷ 广告费），
既不扣退货也不扣成本。只看那个数，很容易把一盘亏钱的生意当成赚的。

这个工具用**同一组参数**同时给四种口径，外加一条保本线：

| 口径          | 公式                           | 看什么                             |
| ------------- | ------------------------------ | ---------------------------------- |
| 广告 ROAS     | 成交额 ÷ 广告费                | 媒体后台那个数                     |
| 扣退货 ROAS   | 净收入 ÷ 广告费                | 退掉之后真实的产出                 |
| 广告 ROI      | 净利润 ÷ 广告费                | 这笔广告费带来了几倍利润           |
| 生意 ROI      | 净利润 ÷ (广告费 + 净货品成本) | 压进去的全部钱回报多少             |
| **保本 ROAS** | 成交额 ÷ 贡献利润              | 低于它必亏；反推即广告费上限       |
| **目标 ROAS** | 成交额 ÷ (贡献利润 − 目标净利) | 想赚 X（或按投产比试算）该跑到多少 |

最后两条是同一条公式：目标填 0 就是保本 ROAS。算出「保本 3.93」只是及格线，
真正要做决策的是「我想赚 500，得跑到 5.46」—— 目标 ROAS 给的就是这个数（示例盘的数，见下面「默认示例」）。

## 两种口径：整盘 / 单件

顶部切换，两边是**同一套公式**的两种读法（单件口径等价于「订单数 = 1、成交额 = 售价、广告费 = 0」）。
所以毛利率、退货修正毛利率、保本 ROAS 两边完全一致，净利润则不同 —— 单件那边不扣广告费。

| 口径 | 输入                                                                                                        | 什么时候用                     |
| ---- | ----------------------------------------------------------------------------------------------------------- | ------------------------------ |
| 整盘 | 成交额 + 订单数（或客单价，两种填法）+ 广告费（填花费或 ROAS，另一个自动换算）+ 成本（比例 / 金额两种填法） | 看一段时间的总投放，盘整个生意 |
| 单件 | 售价 + 单件成本 + 发货 + 佣金 + 退货（**不问投产比**）                                                      | 试一款商品的定价与出价         |

**口径切换放在「投入与成本」面板头部**（不是页顶一条通栏）：它跟 示例 / 清空 一样只作用于输入，
贴在输入面板旁边对得上；原先独占一行通栏、中间全是空档。

**单件口径不问「你现在的 ROAS」**，因为选款与出价阶段最常问的两件事都不需要它：

- **保本 ROAS 是多少** —— 成交额 ÷ 贡献利润，低于它这款货就亏
- **ROAS 做到多少、每件赚多少** —— 一张围着保本线现算的档位表（敏感性面板第一张）

它给出的两个主结果是**每件利润**与**保本 ROAS**（示例盘 17.77 元 / 3.93）：
每件赚多少是这一页最先该看到的数，而保本 ROAS 说的就是**把这件利润全投出去**要跑赢多少才不亏 ——
两者互为倒数（每件利润 ÷ 售价 = 1 ÷ 保本 ROAS）。
「每件可投广告费」是同一个数的投手读法，不再拿它当主结果：它挡住了「这款货到底赚不赚钱」这个更先到的问题。
整盘口径那四个以广告费为分母的 ROI 在单件口径下没有意义（广告费恒为 0），所以整块不显示。

**单件口径的 ② 段**（整盘那边是「广告费上限 + 试算那条线」，见下面「结果卡」）
按**依赖关系**分成两块，前提跟着它管的那几个数走、不集中在段首一条里：

| 位置           | 前提            | 给出的数                                     |
| -------------- | --------------- | -------------------------------------------- |
| 段首           | 假设投产比      | ——（两块都读它）                             |
| 定价反推（元） | 目标净利率      | 保本售价 / 达标最低售价 / 最高可接受单件成本 |
| 规模试算（件） | 固定成本        | 保本销量                                     |
| 〃             | 试算售价 / 销量 | 净利 + 成交额 / 广告费 / 扣广告后每件        |

这么分是因为三格前提管的数完全不同：**目标净利率**改了保本售价不动；**固定成本**只管保本销量，
既不动那三个定价数、也**不进规模试算**（`scaleToBatch` 里 `otherCost` 恒为 0）。
改版前把三格前提挤在同一条里、四个数排成 2×2，于是段头那句「改它们，下面几个数跟着变」是假话，
四个数里还混着「元」与「件/周期」两个量纲，读起来像「第四种定价解」。

只有**假设投产比**留在段首：它是唯一跨两块的前提（定价反推拿它扣广告、规模试算拿它折广告费），
留空取保本线向上取整（贡献利润不为正、没有保本线可取时按不投广告算）。

**这一节里没有一句解释**（段头与两个块标题下都只有标题）：它是结果卡里最长的一块，
而 272px 宽的正文一行只放得下二十来个字 —— 任何一句说明都要吃掉一两行高度。
「谁管谁」改由位置表达（前提就贴在它管的数旁边），口径与公式在说明栏（DocPanel）里逐条写着。

**「定价反推」** —— 反过来解售价与成本上限（定价决策全靠它）。**目标净利率在这一块的标题行右端**
（它只管这一块，跟退货那三个率的开关同一个约定：管一整组的放小节标题行）：

- **保本售价** —— 净利率归零的那个价，低于它必亏。三个数里**只有它不看目标净利率**
- **达标最低售价** —— 给定目标净利率（对售价），最低得卖多少
- **最高可接受单件成本** —— 现价不变、目标净利率不变，成本最多能涨到多少

三个数排成一张**三行的列表**（名称 · 前提 → 数值，一行一个），不再是三张卡：
卡片一个数要占「名称 / 数值 / 注脚」三行加内边距（约 82px），三个并排还会把注脚挤成两行；
列表一行约 28px，三个合起来约 120px，**省掉一半高度**，而三行天然是同一组的三种解法、更像一张表。
保本售价因此不再单独占整行 —— 它「不看目标净利率」这件事写在行注脚里，不靠位置暗示。

目标净利率填的是**率**，定价时心里要的是**数**，所以「达标最低售价」那行的注脚里带着
「每件 X 元」（= 目标价 × 目标净利率，那正是卖到这个价时的净利）。

三个数是同一条式子 `净利 = 售价 × 每元剩余 − 固定花掉的钱` 的三种解法。
**中间量那行摆在数上面**（每 1 元售价剩下多少 + 那行等宽式子）：它是三个数唯一的中间量，
放在下面就成了「看完三个数才知道它们是怎么来的」。它依赖段首那个投产比，所以摆在前提条之后。

**「规模试算」** —— 按件数放大，两个子块**各带自己的前提**，读数就排在各自的前提旁边
（把读数挪到盒子末尾会重演「前提跟结果对不上号」）：

- **保本销量** —— 一份**固定成本**要卖多少件才摊平（单位跟着那格的日 / 月开关走）：
  前提那一行右端直接给「→ 保本销量 X 件/日」，注脚写明口径是**不投广告**
  （分子就是 ① 段那个「每件利润」，所以假设投产比怎么填都不动它）与保本成交额。
  固定成本留空是「还没填」，页面给一句承诺语（填了才有数），不像填了 0 那样照样算
- **「卖多少赚多少」** —— 改售价或改销量，直接给一共能赚多少：
  - 售价那格留空按当前售价；改了价，**单件成本不跟着变**（进价还是那个进价），
    所以成本率、佣金、退货金额全部按新售价重算 —— 不是拿「每件利润 × 销量」乘一下，
    直接乘等于假设进价随售价等比上涨，降价试算会算得偏乐观
  - 销量那格留空按 100 单
  - 广告费按「假设投产比」反推（`成交额 ÷ 投产比`），拿不到投产比就按不投广告算
  - 它的两个试算格与读数在同一条里（`→ 净利 X 元`），下面是**一行**明细：
    成交额 / 广告费（带口径）/ 扣广告后每件。明细不再逐项配公式行 —— 这一块回答的是
    「一共能赚多少」，再挂广告 ROI 与生意 ROI 会把「改售价 / 改销量再试一次」这个动作挤到次要位置；
    要按投产比横向比，④ 段的 ROI 卡与敏感性那张档位表更对得上口径
  - 每件那个数叫**「扣广告后每件」**，跟 ① 段的「每件利润」（扣广告之前）分开叫 ——
    两者只差一个广告费，原先叫「摊到每件」、注脚只说「扣完广告费之后」，看不出差别在哪。
    它按**试算售价**算，所以改了试算售价就不再等于 ① 那个数（那边按当前售价算）

这几格都是**临时试算**，不进输入面板；除**目标净利率**外都不落盘 —— 它是商品的目标净利率，
跟着预设 / 会话快照 / CSV 一起存（`preset.targetMargin`，见「参数预设」那节），
假设投产比 / 固定成本 / 试算售价 / 试算销量则一律不进预设、不进会话快照、也不进 CSV。

## 退货模型：退款分三类，三类的账完全不同

这是本工具跟其它 ROI 计算器最大的差别。大部分计算器只有一个「退货率」，乘在收入上就完事了 ——
那等于假设所有退款都一样：货发出去过、也退回来了。真实场景里不是：

| 退款类型                        | 对应后台的售后类型 | 货的状态         | 要承担什么                     | 不承担什么                       |
| ------------------------------- | ------------------ | ---------------- | ------------------------------ | -------------------------------- |
| **未发货退款**                  | 发货前退款         | 没出库           | 只有那笔订单的推广费           | 货品成本、正向物流、逆向物流     |
| **发货后仅退款**（在途 / 拒收） | 发货后仅退款       | 已发出、原封返回 | 正向物流（已花）+ 逆向运费     | 货值折损（原封件按 100% 能再卖） |
| **退货退款**（签收后）          | 退货退款           | 已签收、再寄回   | 正向物流 + 逆向运费 + 货值折损 | ——                               |

不拆这一层，最常见的错法是**给没发出去的那批货也收了发货运费** ——
示例里未发货退款率 20%，100 单就是 20 单压根没进过快递袋，那 60 元运费不该发生。

「在途退款率」是**选填**的：填了才能把拒收件按「原封可再售」算，
不填就全按签收后退货处理（保守，只会多算损失、不会少算）。它是已发货退款里的一部分，
所以填的数不能高过已发货退款率（超了输入框下面会直接红字拦下，不用等结果卡报错）。

> **填法**：三个率都按**成交订单数**的占比填，也就是后台那三个售后类型的单数 ÷ 成交单数。
> 两类的和就是后台那个「退款率」，可以拿来对账（输入框下面实时显示合计）。
> 手上只有退款金额时，把「退货」组名右边那个开关切到**按金额**，直接填退掉的成交额即可
> （内部按 `率 = 金额 ÷ 成交额` 折回，见「输入项」那节）。

### 未发货退款「零损失」是不是漏算了？

不是。货没出库、运费没产生，它在账面上确实不产生任何损失。它的代价是**那笔推广费**：
广告费已经花了，成交额却没了。示例里约 233 元（= 广告费 × 未发货退款率）。

这个数**不进利润表**：利润表里这件事的体现方式是「成交额少了、广告费没少」，
还包含「本该赚到却没赚到的毛利」，与「退货真损失」不是一个口径。
所以它在结果卡里单独一行说明，不参与加减 —— 拿它去改利润会对不上账。

### 退货真损失剩下的那三块

拆完三类之后，真损失只剩：

- **残损货值** —— 收不回来的那部分，真损耗。**只发生在签收后退货那一类**
  （在途件原封、未发货件没出库）
- **逆向物流** —— 退回的运费，按**已发货退款**的单数计
- **退不回的佣金** —— 平台不退时，已发货退款那部分照样要交（未发货的平台必然退佣）

常见的偷懒算法是「收入按 `成交额 ×(1−退款率)` 算，货品成本却按全量扣」，等于假设退回来的货全废了 ——
那批货的成本上一轮已经付过，再扣一次就是重复计损。

### 「这 35 条我退回给厂家，成本不用出」算了吗？

**算了。** 输入项就叫**「退货能收回的货款（%）」**，退给厂家的货款直接填在这里
（它**只作用于签收后退货**：未发货的货没出库、在途的货原封回来，两者都不该被这个比例打折）：

| 你的实际做法                       | 这一项填 |
| ---------------------------------- | -------- |
| 退回厂家，厂家全额退款             | `100`    |
| 退回厂家，厂家只退八成货款         | `80`     |
| 自己再上架接着卖（按原价卖得掉）   | `100`    |
| 一半退厂家（全额）、一半自己再上架 | `100`    |
| 退回来的全废了                     | `0`      |

示例盘：卖 100 条、退 35 条，收回比例 98% → 净货品成本 **2280.84 元**，折算下来只有 **65.2 件**的货款 ——
退回来那 35 条里，未发货的 20 条没出库（压根不计成本）、在途的 2 条原封、签收后的 13 条按 98% 收回，
真正折损的只有 **0.3 件（9.09 元）**。
把这一项改成 0，净利从 **615.49** 掉到 **170.23**，差的 445.26 就是签收退货那一类少收回的货值。

两个容易填错的点：

- **退回厂家要自己付运费**：那笔钱不进「能收回的货款」，填在「单均退货成本」里
  （这一项同时装着逆向物流与二次质检包装）。示例里填的是 1 元，真实退厂家时通常不止这个数。
- **厂家只退部分货款就等于有折损**：退八成就填 `80`，剩下的两成会按残损计入。

> 为什么不再单独给「退回厂家」开一个输入项：它在**本期成本**上跟「自己再上架」是同一件事
> —— 都是这批货的进价不用再承担一次。差异只在**能收回多少**，而这一层已经被这一个比例盖住了。
> 多一个字段只会让 12 个输入变成 13 个，却算不出不同的数。

## 逐项公式

符号：`G` 成交额 ・ `N` 订单数 ・ `A` 广告费 ・ `c` 商品成本率 ・ `k` 平台佣金率
`L` 单均发货成本 ・ `R` 单均退货成本 ・ `O` 其他固定成本
`u` 未发货退款率 ・ `r` 已发货退款率（= 在途 + 签收后）・ `t` 在途退款率（选填，≤ r）
`s` 退货能收回的货款比例（只作用于签收后退货）
单件口径另用：`P` 售价 ・ `C` 单件成本 ・ `m` 目标净利率（对售价）
假设投产比统一写 `ROAS`（规模试算与定价反推共用）

页面上「从基础量推到保本线」**每一行前面有一个问号图标**（lucide `CircleQuestionMark`），
悬浮（或键盘聚焦、触屏点一下）弹出这一行**用中文写**的算法。解释里**不出现符号** —— 鼠标停上去还要回头查一遍符号表，等于没解释。
气泡是**固定定位**：说明栏是滚动容器，绝对定位的气泡探出容器就被裁掉，最下面几行必然看不到。

```
① 净收入       = G × (1 − u − r)
② 退款金额     = G × (u + r)
③ 发出货品成本 = G × (1 − u) × c
④ 收回货值     = G × c × (t + (r − t)×s)
⑤ 残损货值     = G × c × (r − t) × (1 − s)
⑥ 平台佣金     = 佣金口径 × k
⑦ 正向物流     = N × (1 − u) × L
⑧ 逆向物流     = N × r × R
⑨ 贡献利润     = ① − ③ + ④ − ⑥ − ⑦ − ⑧ − O
⑩ 净利润       = ⑨ − A
保本 ROAS      = G ÷ ⑨
目标 ROAS      = G ÷ (⑨ − 目标净利)   ← 目标填 0 就退化成保本 ROAS
                 （按投产比试算时反过来：广告费 = G ÷ 投产比、净利 = ⑨ − 广告费）

佣金口径       = 退款退还佣金时取 ①（净收入），不退还时取 G − G×u
                 （未发货退款那类平台必然退佣，两种情况都不抽佣）
净利天花板     = ⑨（广告费降到 0 也最多赚这么多，够不到的目标会直接说明）
广告费上限     = ⑨
↳ 还能加投     = ⑨ − A = ⑩ = 当前净利润
单件口径       = N 取 1、G 取售价、A 取 0（只算到广告费之前 → ⑩ = ⑨）
```

最后一行**不是巧合，别去「修」它**：加投到上限时净利正好归零，所以「还能加投多少」与「现在赚多少」
必然是同一个数。示例里两个都是 615.49（1780.49 − 1165），这不是显示重复而是公式的必然结果。

三个利润率（都对着成交额）与三层保本线：

```

毛利率 = 1 − c
退货修正毛利率 = (① − 净货品成本) ÷ G
净利率 = ⑩ ÷ G

只扣货款 = 1 ÷ (1 − c)
再扣退货 = G ÷ (① − 净货品成本)
完整口径 = G ÷ ⑨ ← 出价一律用这条
```

单件口径的 `⑩ = ⑨`（没有广告费可扣），所以第一组第三格在页面上是**净赚比例**而不是净利率。

规模试算（改价时成本率必须重算，`C` 固定）：

```
单件成本 C  = c × G（单件口径下 G = P）
改售价后 c' = C ÷ 新售价          ← C 不变，跟着变的是 c
成交额   G' = 新售价 × 销量
广告费   A' = G' ÷ ROAS           ← 拿不到 ROAS 时按 0（不投广告）
```

单件口径的定价反推：

```

每元剩余 p = 1 − u − r − 佣金口径 − 1 ÷ ROAS
（退款退还佣金时 佣金口径 = (1 − u − r)k，不退还时 = (1 − u)k）

每件真成本 Fc = C × (1 − u − t − (r − t)s) + L × (1 − u) + r × R

保本售价 P₀ = Fc ÷ p
达标售价 Pm = Fc ÷ (p − m)
成本上限 Cm = [P × (p − m) − L × (1 − u) − r × R] ÷ (1 − u − t − (r − t)s)
```

`ROAS` 是结果卡上那个**假设投产比**（原「试算 ROAS」）：单件口径的输入里没有广告费，而「售价定到多少才不亏」
本来就取决于你打算按多少的投产比投 —— 留空就取保本线向上取整的那一档。

口径上的五个决定（页面上有「为什么这么算」逐条解释）：

1. 退款按**未发货 / 在途 / 签收后**三类分别计价 —— 三类的货状态不同，承担的成本也不同
   （未发货的出库都没出、在途的原封返回、只有签收后才会折损）
2. 货品成本按**实际发出量**算 —— 未发货退款那批没出库，不该计成本，也就没有「先按全量算、回头再加回来」这一步；
   退回的那部分靠 `④` 加回来
3. 物流按**实际发出的订单数**计，不按成交额比例 —— 一单一个快递，跟客单价无关；没发出去的那批不产生运费
4. 保本 ROAS 用**成交额**口径 —— 广告后台只认成交额，用净收入口径算出的线不是一个坐标系
5. **残损货值不再单独减一次** —— `⑨` 里没有 `⑤`：货品成本按发出量算（`③`），退回的那部分靠 `④` 加回来，
   剩下的 `⑤` 已经含在「`③ − ④`」里，再减一遍等于把残损扣两次

定价反推里的「每元剩余」跟指标用的是**同一套佣金口径** —— 关掉开关，保本售价、达标售价与成本上限都会跟着变。

## 默认示例（一款成本率 50%、退款率 35% 的商品盘）

成交额 6990 ・ 广告费 1165 ・ 订单 100 单 ・ 成本率 50% ・ 佣金 5% ・ 单均发货 3 元
未发货退款 20% ・ 已发货退款 15%（其中在途 2%）・ 签收退货能收回 98% ・ 单均退货 1 元 ・ 佣金退还

| 项                  | 数                                |
| ------------------- | --------------------------------- |
| 净收入              | 4543.50                           |
| 退款总额            | 2446.50                           |
| ↳ 未发货退款 20%    | 1398.00（20 单，货没出库）        |
| ↳ 在途退款 2%       | 139.80（2 单，原封返回）          |
| ↳ 签收后退货 13%    | 908.70（13 单）                   |
| 发出货品成本        | 2796.00（只算真正发出的 80 单）   |
| ↳ 收回的货值        | +515.16（不是损失）               |
| ↳ 残损货值          | 9.09（只有签收后退货会折损）      |
| 平台佣金            | 227.18                            |
| 正向物流            | 240.00（80 单 × 3 元）            |
| 逆向物流            | 15.00（15 单已发货退款 × 1 元）   |
| **净利润**          | **615.49**（对净收入 13.5%）      |
| 退货真损失          | 24.09（= 残损 9.09 + 逆向 15.00） |
| 广告 / 扣退货 ROAS  | 6.00 / 3.90                       |
| 广告 ROI / 生意 ROI | 52.8% / 17.9%                     |
| **保本 ROAS**       | **3.93** ・ 广告费上限 1780.49 元 |

三个利润率：毛利率 50.0% ・ 退货修正 32.4% ・ 净利率（对成交额）8.8%。
三层保本线：只扣货款 2.00 ・ 再扣退货 3.09 ・ 完整口径 3.93。

这一盘退款率 35% 看着吓人，真损失只有 24.09 元 —— 因为**最大的一块（未发货退款 1398 元）压根没产生损失**：
货没出库、运费没发生。它的代价是那 233 元白花的推广费（= 广告费 1165 × 20%）。

**把三个率填回旧的单档口径**（未发货 0、已发货 35、在途 0），净利会掉到 **520.11 元** ——
同一盘生意、同一批数，两种填法差 95.38 元，全部来自前端那三类没被分开算：

| 差在哪     | 旧口径                   | 新口径                  | 差    |
| ---------- | ------------------------ | ----------------------- | ----- |
| 正向物流   | 100 单 × 3 = 300         | 80 单 × 3 = 240         | 60    |
| 逆向物流   | 35 单 × 1 = 35           | 15 单 × 1 = 15          | 20    |
| 净货品成本 | 3495 − 1198.79 = 2296.22 | 2796 − 515.16 = 2280.84 | 15.38 |

净货品成本那 15.38 里，13.98 是「未发货那 20 单的货（699 元）被按 98% 收回了」，
1.40 是「在途那 2 单的货（69.90 元）被按 98% 打了折」—— 两者都是**重复计损**：
前者货压根没出库，后者原封回来。

> 收回比例取得越高，这一节的差越小（98% 只剩 15.38；示例若按 70% 收，这块差是 230.67）——
> 「三类拆开」的价值主要体现在**收回比例低、退货率高**的盘上。

方向要记住：**旧的单档口径是系统性低估利润**（成本估高）。
它不会让你亏钱而不自知，但会让你把本该加投的盘缩回去。

**切到单件口径**（售价 69.9、单件成本 35、发货 3、佣金 5%、未发货退款 20%、已发货退款 15%（其中在途 2%）、
签收退货能收回 98%、单件退货 1 元）：

| 结果          | 数                                       |
| ------------- | ---------------------------------------- |
| **每件利润**  | **17.77 元**（= 能投出去的广告费上限）   |
| **保本 ROAS** | **3.93**（把每件利润全投出去要不亏的线） |
| 每卖出 100 元 | 净赚 **25.43 元**（保本 ROAS 的倒数）    |

**卖多少赚多少**（售价 69.9、卖 100 单、假设投产比 4）：

| 项       | 数                        |
| -------- | ------------------------- |
| 成交额   | 6990.00                   |
| 广告费   | 1747.50（= 6990 ÷ 4）     |
| **净利** | **29.73 元**（每件 0.30） |

改售价时单件成本仍是 35 元，成本率跟着新售价重算 —— 所以降价不是「少赚差价 × 单量」这么简单。

「ROAS 做到多少、每件赚多少」的档位表围着保本线现算，**10 档**（保本线向上取整那一档为基准，
往前 3 档、往后 6 档，滤掉 ≤ 0 的档位；示例里 3.93 → 中心 4 → 1…10）：

| ROAS | 对应广告费 | 每件净利 |
| ---- | ---------- | -------- |
| 1    | 69.90      | -52.13   |
| 2    | 34.95      | -17.18   |
| 3    | 23.30      | -5.53    |
| 4    | 17.48      | 0.30     |
| 5    | 13.98      | 3.79     |
| 6    | 11.65      | 6.12     |
| 7    | 9.99       | 7.79     |
| 8    | 8.74       | 9.03     |
| 9    | 7.77       | 10.01    |
| 10   | 6.99       | 10.78    |

整盘口径的两张表档位是**写死的 10 档**：退款率 `0…90`（每 10% 一档）、ROAS `1…10`（每 1 一档）。
档位拉密是为了看趋势 —— 5 档时中间那段斜率全被跳过，看不出「退款率涨到哪一档开始吃光利润」。
退款率表扫的是**退款总额**（未发货 + 已发货），三类的相对结构按当前填的比例同比缩放 ——
现实中「退货率涨了」涨的是整体，不会只涨某一类。

**定价反推**（假设投产比留空 → 取保本线向上取整 = 4）：

| 反推            | 数                                          |
| --------------- | ------------------------------------------- |
| 保本售价        | **69.09 元**                                |
| 目标净利率 20%  | 最低售价 **151.59 元**                      |
| 目标净利率 20%  | 最高可接受单件成本 **14.03 元**（现 35.00） |
| 每 1 元售价剩余 | 36.75%                                      |

两组示例用的是**同一个模型**：单件口径就是把一单商品折算成整盘来算 —— 订单数 = 1、成交额 = 售价、广告费 = 0。
成本率可以不同：整盘按 50% 填（商品成本 3495 ÷ 6990），单件按 35 ÷ 69.9 ≈ 50.07% 填。
所以这是**同一套算法、不一定同一组数** —— 两份示例的成本率差 0.07 个百分点，
单件保本 ROAS 与整盘显示出来都是 3.93（精确值 3.933 与 3.926），档位表的每件净利与「整盘净利 ÷ 100」
也差几分钱，正是这个四舍五入带来的，不是约定两边必须相等。

广告费**之前**的指标两类口径各走各的：单件的「净利润」就是贡献利润（广告费那项恒为 0，没得扣）。
整盘那边另扣 1165 元广告费，摊到 100 单正好是每件 11.65 元。

## 输入项

| 口径 | 组   | 字段                                                                                                                              |
| ---- | ---- | --------------------------------------------------------------------------------------------------------------------------------- |
| 整盘 | 成交 | 广告花费 / 广告 ROAS（两种填法，填一个另一个自动换算）、成交额 ★、订单数 ★（**或客单价**，两种填法，另一个自动推）                |
| 整盘 | 成本 | 商品成本 ★（比例 / 金额两种填法）、平台佣金率、单均发货成本、其他固定成本                                                         |
| 整盘 | 退货 | 未发货退款 ★、已发货退款 ★、其中在途退款（选填）、退货能收回的货款、单均退货成本、退款是否退还佣金（前三格**率 / 金额两种填法**） |
| 单件 | 商品 | 售价 ★、单件成本 ★、单件发货成本                                                                                                  |
| 单件 | 平台 | 平台佣金率                                                                                                                        |
| 单件 | 退货 | 未发货退款 ★、已发货退款 ★、其中在途退款（选填）、退货能收回的货款、单件退货成本、退款是否退还佣金（前三格**率 / 金额两种填法**） |

★ 是带必填标记的字段。判断标准是「缺了会不会**静默算出一个看起来合理的错数**」：
商品成本不填就是成本 0、毛利率 100%，比报错更危险。标记只做提示（`*` + 读屏可读的「（必填）」），
不在前端拦输入 —— 这一页没有「提交」这个动作，每敲一个字符就算一次。

首屏预填的是**示例数据**，表单顶部有一条蓝色提示写明这件事；改动任意一项后提示自己消失
（`isExample`）—— 不标出来的话，用户改两个字段就可能把示例数当成自己的结果发出去。

**填错的东西就地报在字段下面**：解析层返回的每条错误都带着「是哪一格」（`ParsedField`），
`ui/NumberField.svelte` 据此把红字挂到那一格的输入框下方，同时给它 `aria-invalid` 与
`aria-describedby`（读屏 Tab 进去就念得到）。有红字时那一格的补充说明让位给红字 ——
两句一起念会把「先修哪个」淹掉。结果卡与敏感性卡因此只说「有参数还不对，按标红那项改」，
不再把同一句话抄第二遍。

单件口径**没有广告费 / 投产比**这一项：它算的是广告费之前的账。要按某个投产比算「卖多少赚多少」时，
在结果卡 ② 段的**「假设投产比」**里临时填一个 —— 它是那一页唯一跨两块的试算前提
（定价反推据它扣广告、规模试算据它折广告费），不占输入位、也不进预设。

费率一律按**成交额的比例**填（填百分数），**退款按成交订单数的占比**填（能直接跟后台那三个售后类型对账），物流按**单 / 件**填。

「退货」那三格（未发货 / 已发货 / 其中在途）有**两种填法**，整组一个开关、贴在「退货」组名右边（`RefundMode`）：

- **按比例** —— 填退款率（%），能直接跟后台那三个售后类型对账
- **按金额** —— 填**退掉的成交额**（元），按 `率 = 金额 ÷ 成交额` 折回；单件口径的成交额就是售价，
  所以那边填的是**每件退多少钱**（示例里未发货退款 13.98 元/件）

切换时三格一起换算数字（跟成本、广告那两处同构，不是只换单位）。按金额填时**要求成交额已有值**
（单件口径是售价），否则报「按「退款金额」填时要先把成交额填好」；金额高过成交额等于率超过 100%，
也一并拦下。**整组一个开关而不是各给一个**，是因为「在途 ≤ 已发货」是这三格之间的约束 ——
一格填率、一格填金额的话这条约束没法直接比（越界的错误消息也按你填的单位说，
不把「1048.5 元」换算成百分比再报给你）。按金额填时，输入框下面那行合计也从「合计退款率 X%」
改成「合计退款金额 X 元」。结果卡 ③ 的「退货这笔账」**始终按率列三类** —— 那是折回后的结果，
跟你填的是率还是金额无关；复制摘要则回显你填的那个口径（金额就写「未发货退款金额 1398 元」）。

整盘的广告费同样有**两种填法**，开关是**「广告花费（元）」这个字段名右边那枚「花费 ⇄」**
（`AdMode`，点一下换成「ROAS ⇄」）：

- **花费** —— 直接填这段投放花了多少钱（元）
- **ROAS** —— 填媒体后台那个 ROAS，广告费按 `成交额 ÷ ROAS` 换算出来

它原先跟商品成本、退款那几处一样是「小节标题行右边的分段按钮」，搬下来有两个理由：
一是**它只管这一格**，贴在那个名字旁边才看得出管的是谁（原先要跨半行去对）；
二是**省一半宽度** —— 两个选项来回切的场景，一枚按钮比两枚分段按钮窄一半，
这一格在最窄的 `lg` 档只有约 151px。交换图标（lucide `ArrowLeftRight`）是「点一下换到另一种」的意思，
跟数字跟着换算这件事对得上（不是「选一个」，是「换成另一个」）。
**订单数、商品成本那两格后来也搬成了同一枚按钮**（同一个 `MODE_SWAP_BTN`），三处形态一致 ——
按钮文案一律**不带「按」字**：它紧跟字段名，连起来读已经是「广告花费 · 花费」，那个介词是多余的。

切换时数字跟着换算，跟商品成本的两种填法同构。**输入框下方那行提示栏**会实时显示换算结果：
按花费时给「广告 ROAS = 成交额 ÷ 广告费 → 6.00」，按 ROAS 时给「广告费 = 成交额 ÷ ROAS → 1165.00 元」——
填一个就能看到另一个，不用自己按计算器。

按 ROAS 填时**要求成交额已有值**：ROAS 的分母是广告费、分子是成交额，成交额是 0 就解不出来。
这时报「按广告 ROAS 填广告时要先把成交额填好」，不按 0 硬算。

整盘的「商品成本」有两种填法，开关是**「商品成本率（%）」这个字段名右边那枚「比例 ⇄」**
（`CostMode`，点一下换成「金额 ⇄」）：

- **按比例** —— 填成本率百分数（≤ 100%），跟佣金率一样是成交额的比例
- **按金额** —— 填进货价（元 / 件），按客单价（成交额 ÷ 订单数）折算成成本率

差别的实质是**你手上有什么**：运营拿到的货价是「进价 35 元」这种绝对值，
换算成成本率经常除不尽（35 ÷ 69.9 = 50.0715…%），只能填个近似值。

切换时框里的数字跟着换算，**不是只换单位** —— 只换单位的话，「50」会从 50% 静悄悄变成
50 元 / 件，同一串字符含义全变。客单价还拿不到（成交额或订单数是 0）时数字原样留着，
由校验消息说明「要先填成交额与订单数」。

「按金额」这一路**不设 100% 上限**：进价高过售价是真实存在的经营状况（清库存、引流款），
该算出一条负毛利率，而不是弹个错把人拦住；「按比例」仍卡 100%，超过必然是笔误。
单件口径那格同理 —— 它的「单件成本」也不设「不能高于售价」的上限，两个口径对同一件事的处理一致
（结果就是每件利润为负，结论句直说「这个价每件亏 X 元」）。

「订单数（单）」这一格也有两种填法（`OrdersMode`），开关同样是**字段名右端那枚「单数 ⇄」**
（点一下换成「客单价 ⇄」）：

- **按单数** —— 直接填这段时间成交了多少单
- **按客单价** —— 填客单价（元/单），订单数按 `成交额 ÷ 客单价` 换算

运营手里常常只有「客单价 69.9 元」这个数，或想按某个客单价试算订单量 —— 让人先做一道除法
才能开始算，是纯粹的拦截（跟商品成本、广告那两处同一个理由）。切换时数字跟着换算，
两个方向都是 `成交额 ÷ 当前值`（订单数 = 成交额 ÷ 客单价、客单价 = 成交额 ÷ 订单数），
所以跟广告那格一样**不需要知道要切到哪个填法**；成交额拿不到时数字原样留着，不猜。

换算出来的订单数**可以是小数**（6990 ÷ 70 = 99.86 单）：物流、退款这些本来就是按单摊的，
四舍五入反而会让各项对不上账，显示时才由 `formatCount` 取整。
「按客单价」填 0 会除出 Infinity，这时才拦（报「客单价要大于 0」）；**留空按没填处理**，
不报错也不算出一盘假数。客单价这一路只影响订单数这一个数 —— 成本按「元/件」填时用的客单价
取自折算后的订单数，所以两种填法下成本率算出来是同一个值。

**开关的摆放按作用范围定**：管一整组的放**小节标题行右边**（现在只剩退货那三个率的 `RefundMode`，
`SECTION_HEAD`），只管一格的贴**字段名右端**（`NumberField` 的 `labelExtra`：广告花费 / 订单数 /
商品成本三处）。位置本身就是作用范围 —— 原先管一格的开关也塞在标题行里，看着整齐，
实际离它管的那格隔了半屏。

组级开关之所以不能往字段格里塞：**字段格在 lg / 2xl 两档只有 150–167px**
（`FIELD_GRID` 在这两档是 2 列）：两枚文字按钮塞进 150px，数字就只剩三四个字符；
试过把它缩成图标、贴进输入框内部右端（跟清空 × 并排），`34.95` 就已经放不下了。
标题行横跨整个字段网格（约 256–576px），放得下。

字段级那枚窄按钮的尺寸是**按最挤的一格倒推的**：整盘口径里最长的是「单件成本（元/件）」106px
配 2 字按钮、「客单价（元/单）」94px 配 3 字按钮，而 2xl 档字段只有 167px —— 所以内边距收到 `px-1.5`、
图标 `size-3`、字图间距 `gap-0.5`（2 字按钮 50px、3 字 62px，`106 + 8 + 50 = 164 ≤ 167` 才刚好放得下）。
按钮高 24px 是触控目标下限（axe `target-size`），而字段名的行高只有 16px —— 照 24px 排版会把这一格的
标题行顶高，同排另一列的输入框跟着掉 8px（两列的输入框不在一条线上），所以用 `-my-1` 把上下各 4px
的盒模型吃掉，按钮在行里只占 16px。真摆不下时标题行是 `flex-wrap`，换行总比把数字挤没强。
`aria-label` 说清「当前按花费填，点击换成按 ROAS」。

小节标题行那个组级开关用 `SegmentedControl` 的**轻档**（`tone="quiet"`：选中是浅蓝底 + 蓝字、
按钮更矮更窄 `h-7 px-2.5`）—— 一屏里会同时出现面板头部的口径 + 两处退货，实心蓝块会互相抢镜头，
控件比它自己那行 12px 的标题还响；轻档把这个主次扳回来。高度也矮一档（`h-8` → `h-7`）：
旁边就是 12px 的小节标题，32px 的按钮框比标题高出一倍，这行看着像开关在主导，不是标题。
**面板头部的口径切换仍用默认档**（实心蓝、`h-8`），两档拉开层次：面板级最重、小节级次之。
移动端那个「收起」按钮跟着做成 `h-7`，跟同排的分段按钮等高（UI-STYLE §9）。

单件口径没有「其他固定成本」（它没有输入位，`parseUnitInputs` 里恒为 0），
所以单件口径的利润明细里**不显示这一行** —— 摆一行恒为 0 的成本只会让人以为漏填了。

每个数值字段填了内容之后右侧会有一个清空按钮（`ui/NumberField.svelte`），点一下把这一个字段置空。
它**默认透明、悬浮或聚焦到该字段才显形**（二十来个字段常摆二十来个 × 太吵，而且它贴着输入框右边缘，
常显会被当成输入框的一部分）；键盘与触屏都走 `group-focus-within`（Tab / 点一下输入框就显形），
所以**不再**给触屏开一条「常显」—— 那等于手机上十几个字段各挂一个 ×。
空串按 0 处理，所以清掉某项等于把它按「没有这笔成本」重新参与计算。
输入框里**只显示你敲的那个数**，不做任何回显格式化（`6990` 就是 `6990`）。
**这一页的数字一律不加千分位**（`11650.00` 而不是 `11,650.00`）：一头要对上输入框里敲的那串、
一头要贴到群里让人照着复算，两处写法不同会让人怀疑是不是两个值；代价是大额要靠数位读量级。
口径在 `core/format.ts`（也没用 `Intl`：它按 locale 输出，SSR 与浏览器不一致时水合会闪）。

整个面板一起清零用输入面板头部的「清空」——它是这一页唯一的破坏性操作（十几个字段一次性清掉、
且进不了预设回退），所以**先弹一次确认**（原生 `confirm`，跟 websocket 的「恢复默认预设」同一个做法）。

**切口径后来回试同一款货**时，「退货」组下面那行会给一个「带入整盘的退款参数」（反向是「带入单件」）：
三个退款格走**源 → 率 → 目标**两跳 —— 两边的成交额不是一个量级（整盘是成交额、单件是售价），
而且各自可能按率或按金额填；收回比例、退货成本、佣金退还开关两边同义，原样搬。
另一套还没填、源本身有错、或这一套按金额填却缺成交额时，它只提示原因、不动手。

## 参数预设（左栏）

一条预设是**整组快照**：口径 + 两套输入 + 目标净利率。存两套输入是有意为之 ——
「存的时候在看整盘、切到单件试完价再切回来」是这工具最常见的用法，只存一套的话另一套参数会在切口径时丢掉。

**当前输入本身也会自动存一份**（键 `toolv:ecommerce-roi-inputs`，300ms 防抖、示例态不写）：
刷新或关掉再回来，上次填的那组参数连同口径、目标净利率都还在，不必先存成预设。
两者的分工是：预设**有名字、能导出、能并列多条**，是「主动留档」；这份只是「别让我重填」。
会话快照与预设共用同一份字段校验（`parseSession` / `parsePresets` 都走 `readTexts` 那套），
坏数据整份丢弃而不是恢复成半套；**试算类输入两边都不进**（假设投产比 / 试算售价 / 试算销量 / 目标净利或按投产比的试算）。

**试算类输入一律不进预设**：假设投产比（原试算 ROAS）、试算售价、试算销量、目标净利 / 按投产比的试算 ——
前两个跟着保本线自动推出默认值，属于「临时试算」而不是商品参数 ——
存下来的话，下次应用预设它会对着上一个商品的保本线说话。留空就永远跟着当前输入走。

- 填好参数后在最左栏顶部填个名称点「保存」，整组参数存进 `localStorage`（键 `toolv:ecommerce-roi-presets`）
- 点条目一键回填（连口径一起切）；悬浮时**右下角**出现垃圾桶可删除、**右上角**出现复制图标可把名称拷走
  （整条是按钮，名称那串字拖不出选择，所以复制给了显式入口 —— 两个图标都是条目的兄弟节点，
  HTML 不允许 button 嵌 button，视觉上靠绝对定位落进条目内）
- **左侧手柄可拖动排序**：按住拖到哪条，这一条就排到哪条的位置，顺序随预设一起存进 `localStorage`。
  手柄聚焦后按 ↑ / ↓ 也能移动一条 —— 只给拖动的话键盘用户就完全排不动。
  **只有鼠标移到手柄那一块才显形**（不是悬浮整条就冒出来）：排序不是每条都要做的事，
  跟复制 / 删除抢位置没必要；`opacity-0` 的元素照样接得住指针事件，移上去照样显形、按下去就能拖
  实现走**指针事件**而不是 HTML5 拖放（`draggable` + `dataTransfer`）：后者在触屏上一次都不触发
- **悬浮条目会在右侧摊开这条预设的全部参数**：照输入面板分组（成交与广告 / 成本项 / 退货），
  组内**一字段一行、左名右值**。数据与复制摘要同一份（`summaryInputGroups` / `summaryUnitGroups`），
  只是那边拼成一句话好贴到群里、这边排成两列好扫。没填的字段不出现，整组都空的不画标题；
  一条参数全空的预设干脆不出卡。卡片是固定定位，滚动或改窗口尺寸会收起 —— 坐标是算出来的，条目滚走了它就失效
- 标题行右侧「导出」下载一份 JSON，「导入」从文件追加合并 —— 换台机器 / 换个浏览器接着用
- 导入逐条校验字段，任一条不合法就整份拒绝并说明原因，不会给你半套数据
- 隐私模式下 `localStorage` 不可用，读写整段跳过，不影响计算

两个图标的定位是**跟它们管的那一行对齐**的，不是贴着条目外框：条目是 `p-2`（8px），
名称行占 8–24px、中心在 16px；复制按钮 `top-1 right-1`（4px）后占 4–28px，中心也是 16px
—— 删除按钮同理落在摘要末行的中心。右端让位也跟着算过：名称行 `pr-7`（28px）
= 按钮 24px + 与徽章之间 8px 的间隙（原先 `pr-6` 只留 2px，按钮像是压在徽章上）。

## 预设 CSV：一行一条，带结果与利润明细

预设除了 JSON 备份，还能导出成 **CSV**（标题行右侧那个 `CSV ▾` 下拉）。两件事不是一回事：

|      | JSON                     | CSV                                             |
| ---- | ------------------------ | ----------------------------------------------- |
| 用途 | **备份**：原样存回       | **对比**：几套参数摆在一起比保本线、净利        |
| 形状 | 预设数组（每条一组嵌套） | 宽表：**一行一条预设**，列 = 参数 + 结果 + 明细 |
| 结果 | 不写（应用时才算）       | 写进去（保本 ROAS / 净利 / 各项成本…）          |
| 导入 | 原样恢复                 | 只认**参数列**，逐条追加为新预设                |

**一次只处理一种口径**（下拉里选「整盘」还是「单件」）：整盘问「成交额 + 订单数 + 广告费」、
单件问「售价 + 单件成本」，参数集合不同，混一张表会有半数列是空的 ——
导出因此只含该口径的预设，导入也按该口径去认列。

列分三段，**结果列一律是换算后的数**（`广告费（元）`、`广告 ROAS`、`保本 ROAS`、`净利润（元）`
、`净货品成本（元）`…），所以挑几列直接排序 / 拉图表就能回答「哪一套更强」；
百分数写成数字（`净利率（对成交额，%）` 列里是 `8.8`），Excel 里能直接排。
**参数列回显用户填的原始值**（按 ROAS 填广告就写 `6`），另配一列「广告填法」说明它是什么 ——
回填看参数、对比看结果，两边都不用猜。非有限的结果（贡献利润 ≤ 0 时的保本线）留空，不写 `NaN` / `Infinity`。

导入时**结果列整段忽略**：那是算出来的，改了也不影响计算（而且多半是在 Excel 里动过的）。
另一套口径沿用**当前**这一组 —— 跟「保存预设」一次存两套同一个理由。
任一行任一格认不出来（填法值不是「按花费 / 按 ROAS」、参数列填了中文数字）就**整份拒绝**并报出行号，
跟 JSON 导入同一个口径：半套参数比没有更麻烦。
没有「名称」列时按行号补「导入预设 1 / 2」；文件带 BOM（Excel 存出来就有）、字段带引号逗号都能读。

条目本身显示**名称 + 口径徽章 + 摘要**，摘要只放**最能区分两条预设的两个数**：
整盘给「广告 + 成交额」（一头是投进去的钱、一头是换回来的成交额），单件给「售价 + 单件成本」。
其余参数不往摘要里塞 —— 悬浮条目会摊开全部（见下），
而摘要在 16rem 宽的栏里本来就是两行起步，塞三个数就变成四行。
摘要排在名称下面一行、允许折行（左侧栏窄，截断等于只剩第一段）。

组件这一层也拆开了：面板的壳（头 / 名称输入 / 列表 / 导入导出）在 `$lib/components/PresetPanel`，
**一条预设长什么样在它的 `PresetItem.svelte`** —— 想整个换掉就传 `item` snippet，
不必再往面板里加 prop。悬浮参数卡的内容另走 `detailGroups`（分组 + 左名右值）：
组件只声明「要什么形状」，数据仍由本工具的 `core/presets.ts` 给。

**拆分前的老预设文件照样能导入**：老文件里只有一个 `returnRate`，迁移时整份落进「已发货退款率」、
另两类补 0 —— 三类退化成一类，算出来的数与当时**逐位相同**（`migrateRefundFields`，单测里有断言守着）。

## 结果卡：按「你会问什么」分 4 段

不是按「口径完备性」排的 —— 打开这一页只有几个问题，段的顺序就是答案的顺序。
每段一条分隔线 + 一个段标题；**同一件事只说一遍**是这个布局的硬约束。

| 段               | 位置                                                                                                                                                                         | 回答的问题                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| ① 结论           | 保本 ROAS ｜ 净利润（两个数盒，各带公式代入）→ 结论条 → 一行比率                                                                                                             | 最低多少才不亏？这次投入赚了多少？离保本线还有多少余量 |
| ② 试算与下一步   | 整盘：广告费上限 + 试算那条线（**按净利 / 按投产比二选一**，给出投产比 · 要投入 · 赚多少）；单件：**定价反推 + 规模试算两块**（前提各跟各的数走，见前面「单件口径的 ② 段」） | 按什么假设、我该投到多少 / 一共能赚多少                |
| ③ 这笔钱怎么来的 | 利润明细 + 退货这笔账（**按三类分列**）                                                                                                                                      | 钱是怎么来的 —— 收入减各项成本，逐行能自己核对         |
| ④ 比率与口径     | 4 个 ROI + 3 个利润率**合成一组卡** + 三层口径折叠                                                                                                                           | 跟平台后台、同行的数对上                               |

（单件的定价反推**不再是独立的 ⑤ 段**：它跟规模试算解的是同一条式子，分成两段会让前提与口径
各写一遍 —— 合并之后又发现三格前提挤成一条、四个数混两个量纲，所以这一版按依赖重新分成两块。）

段是怎么来的 —— 改版式前先看这三条，否则会把已经解决的问题重新犯一遍：

- **保本线大块拆掉了。** 它原先装三样东西，三样都不该在那儿：大数字与公式代入在 ① 的数盒里已经有了
  （保本 ROAS 一度在一屏里出现三遍：顶部盒 / 保本线块的块顶 / 那个块里的说明）、三层口径是「解释别人算的线为什么更低」
  的材料（归 ④，仍是折叠）、广告费上限与试算那条线是**决策输出**，原先压在倒数第二块、要滚过十一块才看到（归 ②）。
- **② 先给结论、③ 再给依据。** 「卖多少赚多少」是结论，「钱怎么来的」是依据 ——
  反过来会让人在这页滚半天还没看到自己的答案。
- **比率合成一组。** 4 个 ROI 与 3 个利润率是同一类东西，原先拆成两组、两套列数（2 列 / 1 列 / 3 列），
  中间还夹一个标题与两句说明 —— 同一块面板里列数来回跳，是最直接的「乱」。

**单件口径下这张表有五处换说法**（它只算到广告费之前）：

| 位置           | 整盘口径                                                                   | 单件口径                                      |
| -------------- | -------------------------------------------------------------------------- | --------------------------------------------- |
| ① 顶部右边     | 净利润（当前 ROAS 降为它那行小字；没投广告时那行改说「本期没有广告投入」） | 每件利润（= 能投出去的广告费上限）            |
| ① 比率那一行   | 净利率                                                                     | 每卖出 100 元净赚多少（保本 ROAS 的倒数）     |
| ④ 四个 ROI 卡  | 四个口径并排                                                               | 整块不显示（广告费恒为 0，那几格是 Infinity） |
| ③ 利润明细合计 | 净利润                                                                     | 每件利润                                      |
| ② 广告费上限   | 整盘才说                                                                   | 不重复显示（同一个数已在 ① 的盒子里）         |

两处刻意的选择：

- **「账」排在「比率」前面。** 利润明细是全页唯一不需要懂任何 ROI 口径、逐行能自己核对的东西，
  也是结论可不可信的依据。原来它在最底下，要滚过八张指标卡才看得到 —— 把最可读的东西埋在最深处是反的。
- **口径解释一律收进 `<details>`。** 三层口径、以及「退货为什么只有这几块才是真损失」，
  都是「想核对时才看」的材料，不是每天要看的数；用原生 `<details>`：零 JS、键盘可达。
  要记住的那条（完整口径）在 ① 的数盒里已经给了。

结论条只报「离保本线还有多少余量」，不再重复右盒那个净利金额（已经是大字）与左盒的保本线 ——
同一件事说两遍会让真正的新信息（安全边际）淹掉。

### 列数只跟面板宽度走（容器查询）

结果面板挂 `@container`，里面所有卡片网格用容器断点，**不用 `sm:` / `xl:` / `2xl:` 视口断点** ——
这块面板的宽度不随视口单调递增（`lg` 三栏生效、`xl` 中栏再分列、`2xl` 说明栏加宽都会让它变窄），
按视口写会在这些档上把列数跳来跳去（跟敏感性两张表同一个理由）。

| 面板宽 | 来自哪档 | 7 张比率卡 |
| ------ | -------- | ---------- |
| 304px  | 1280     | 2 列       |
| 464px  | 1536     | 3 列       |
| 784px  | 1920     | 3 列       |

阈值也是**实测倒推**出来的，不是「够放就行」：卡从 2 列掉回 1 列会多出 3 行，比合并两组省下的还多
（1280 档实测：这一整段排 2 列 641px、排 1 列 849px，结果卡内容跟着从 2073px 长到 2281px），
所以窄面板也必须两列。
而只需要 288px（`@2xs`）与 448px（`@md`）两个阈值：前者让 304px 每张 136px —— 跟旧版 ROI 卡同宽；
后者让 464px 每张 140px —— 跟旧版利润率卡同宽。两档都是这个面板原本就接受过的宽度。
（② 段单件那三个定价数改成了列表，不再吃这两个阈值 —— 一行一个数，多宽都不改列数。）

两个数盒（`grid-cols-2`）与三层口径的 3 个小格是**定列数**，不参与升档：前者是「最该第一眼看到」的两个数，
后者只是三个短数字。

## 算完之后：下一步动哪个

上面三个数只说明「我现在什么水平」，真正的决策在后面两步：

- **试算那条线**（结果卡 ② 段里）
  两个数说出来就是这条线的全部：**投产比**、以及它对应的**要投入多少广告费 / 能赚多少净利**
  （广告费 = 成交额 ÷ 投产比 = 净利天花板 − 净利 —— 三个数其实只有一个自由度）。
  所以目标有**两种填法，二选一**（跟成本 / 广告 / 退款 / 订单数那几处同构，开关在那一行的标题行右侧）：
  - **按净利**（元）：填想赚多少钱，报出需要跑到的投产比与要投入的广告费，再加
    「现在还差多少 / 还有多少余量」。目标超过净利天花板（贡献利润）时直接说够不到。
  - **按投产比**：填一个投产比，报出要投入多少广告费、能赚多少。目标填 0 时广告费正好等于
    广告费上限、净利归零 —— 保本线与上限本来就是同一条线。
    切换填法时数字跟着换算（`投产比 = 成交额 ÷ (天花板 − 净利)`），而不是让你同时填两个互相打架的数。
    按投产比填时留空取保本线，跟按净利填 0 落在同一条线上。
    整盘口径的「广告费上限」跟它同一段 —— 上限是「最多能投多少」，这条线是「按这个投产比要投多少」
    （或「想赚 X 要投到多少」），同一件事的两半，别再隔十一块远。
- **下一步最值的一项**（敏感性面板第一行）
  把商品成本率、佣金率、三个退款率（未发货 / 已发货 / 在途各自单列）、收回比例、发货 / 退货成本、
  广告花费各往两头试 10%，
  报出「改善它净利涨得最多」的那一项（示例盘里是商品成本率，降 10% 多赚 228 元）。
  只报一个：12 个输入摆在那里，给一张表等于没给。
  它**原先长在结果卡的结论下面**，跟两张敏感性表回答的是同一个问题（动哪个变量、动多少会怎样），
  所以搬到一起；结果卡那边把那两行让给了数字。

另外两处围绕「别看错、别传错」：

- **复制摘要带完整输入，按钮就长在结果卡标题行右侧** —— 摘要除了结果，还按输入面板的分块
  （成交与广告 / 成本项 / 退货，单件口径是 商品 / 平台 / 退货）**回显用户填的每一个数**，
  贴到群里别人能照着这组数自己复算一遍。三个硬讲究（`summaryInputs` / `summaryUnitInputs`，
  与预设悬浮卡共用 `summaryInputGroups` / `summaryUnitGroups` 那份数据）：

  - **回显原始字符串、不做任何换算** —— 按「广告 ROAS」填就写「广告 ROAS 6」，
    按金额填成本就写「单件成本 35 元/件」。换算过的数跟用户看到的输入框对不上
  - **没填的项整项不出现**：空串在计算里按 0 处理，但「没填」与「填了 0」是两回事，
    写一行「单均退货成本 0 元」会被读成「真有这么一项、金额就是 0」。整组都空就整组不出现
  - **佣金一定带上「退款退还 / 不退还」**：它决定佣金按净收入还是按成交额抽，只报一个 5% 会算出另一个数

  按钮放结果卡头部而不是页顶通栏：它只作用于结果，原先隔着一屏，按下去要回头看是指哪块

- **敏感性表配迷你折线** —— 手写 SVG（`ui/Sparkline.svelte`），零依赖；整块 `aria-hidden`，
  数字在表里已经有一份，读屏不重复念。折线**跳过非有限点**：某一档的贡献利润被成本吃光时，
  保本 ROAS 会算成 `Infinity`（`formatTimes` 出「—」），那一点就不画；横轴仍按原始档位数均分，
  行的位置不会窜

## 界面布局

桌面（lg 起）是三栏，三栏等高、各自滚动（`ToolShell` 走 `fill="fill"` + `fillFrom="lg"`）：

| 栏  | 宽         | 放什么                                                                                             |
| --- | ---------- | -------------------------------------------------------------------------------------------------- |
| 左  | `16rem`    | 参数预设（保存 / 应用 / 导出导入 JSON / CSV 下拉），面板内滚                                       |
| 中  | `1fr`      | 左右两列：**左列整列「投入与成本」** ｜ 右列上下「结果（复制摘要在其头部）+ 敏感性」；无整宽工具条 |
| 右  | `20–28rem` | 说明：符号表、逐项公式、三个利润率、定价反推、九条「为什么」，面板内滚（分四档，见下）             |

说明栏的宽度分四档，**每档都是「中栏还剩多少」反推出来的**（改版式前先把这几条算式核一遍）：

| 档位             | 说明栏  | 中栏   | 中栏右列  | 依据                                                                                   |
| ---------------- | ------- | ------ | --------- | -------------------------------------------------------------------------------------- |
| `lg` 1024 起     | `22rem` | 352px  | —（单列） | 中栏纵向堆三块，没有左右之分                                                           |
| `xl` 1280 起     | `20rem` | 640px  | 304px     | 右列正好 304px（两列指标卡的下限 300px），左列才拿得到 `20rem`；说明栏因此让出 2rem    |
| `2xl` 1536 起    | `22rem` | 864px  | 464px     | 仍在敏感性并排的 448px 阈值之上，让出的 2rem 给了左列（`24rem`，字段网格每格约 168px） |
| `120rem` 1920 起 | `28rem` | 1152px | 752px     | 中栏本身有富余                                                                         |

说明栏里是等宽公式长串（`whitespace-pre`）与中文长段，宽一点直接减少公式块的横向滚动；
但中栏右列（结果 / 敏感性）有硬下限，所以在 `xl` / `2xl` 这两档**说明栏让了 2rem 给「投入与成本」**——
输入那栏原来在 `xl` 只有 `18rem`（比 `lg` / `2xl` 的 352px 还窄），字段格里的填法开关都摆得下不去脚。

**控件都贴在它作用的那块上**，不再有一条通栏工具条：口径切换与 示例 / 清空 进「投入与成本」面板头部
（只作用于输入），「复制结果摘要」进「结果」面板头部（只作用于结果）。
通栏会把口径孤零零摆在一行、右边留一大片空档，而且复制按钮离结果卡隔着一屏。

### 中栏内部

| 断点          | 排法                                                                                            | 中栏实际宽  |
| ------------- | ----------------------------------------------------------------------------------------------- | ----------- |
| `< lg`        | 单列纵向堆叠：投入与成本 → 结果 → 敏感性，页面自然流                                            | 约 350px 起 |
| `lg` – `xl`   | 三栏生效后中栏被两侧栏挤窄，仍纵向堆三块，行高 `1.5fr / 1fr / 1fr`（投入最需要高度）            | 约 350px    |
| `xl` 1280 起  | 左右两列：`20rem` **投入与成本（`xl:row-span-2`，占满左列整列）** ｜ 右列上「结果」下「敏感性」 | 640px       |
| `2xl` 1536 起 | 同上，左列放宽到 `24rem`（内容区约 352px，字段网格排两列、每格约 168px）                        | 864px       |

`xl` 才开始左右分栏，是被宽度算出来的：右列最少要 300px 才放得下两列的指标卡（每张约 136px）
与结论条，于是输入那一列拿剩下的部分；`lg`–`xl` 之间中栏只有约 350px，
分两列每边不足 170px，必定挤坏 —— 所以那个区间走上下堆叠。

右列两行按 **`1.5 : 1`** 分 —— **结果拿大头，不跟敏感性平分**。实测（Playwright）：

| 视口      | 中栏高 | 结果  | 敏感性 |
| --------- | ------ | ----- | ------ |
| 1280×900  | 812    | 478px | 318px  |
| 1536×900  | 812    | 478px | 318px  |
| 1920×1080 | 992    | 586px | 390px  |

结果卡是这一页的主产出（两个数 → 结论 → 这笔钱的账 → 口径交叉验证），本来就远长于一屏，
多给的高度换来的是**少滚一段**；敏感性是「对照着看」的材料，整块内滚一点不伤它的用法。
**代价**：1536 及以上敏感性已经转成左右并排（整块约 475px），318px 要内滚约 157px ——
这是主动选的：宁可让对照表滚，也不让结果卡滚。
也不能给它 `auto`：那会吃掉整列，结果卡直接废掉。要调系数就动 `xl:grid-rows`（`lg` 档三行同理，见下）。

**敏感性两张表：面板自己的宽度够就左右并排**（容器查询，不是视口断点）。实测：

| 视口 | 中栏 | 右列（= 面板宽） | 两张表各宽 | 排法         | 面板内滚（行高 1.5:1 下） |
| ---- | ---- | ---------------- | ---------- | ------------ | ------------------------- |
| 1280 | 640  | 304              | 270        | 上下排       | 514px                     |
| 1400 | 728  | 424              | 390        | 上下排       | 498px                     |
| 1426 | 754  | 450              | 200        | **左右并排** | **157px**                 |
| 1536 | 832  | 464              | 208        | 左右并排     | 157px                     |
| 1920 | 1152 | 752              | 368        | 左右并排     | 69px                      |

1536 / 1920 两行的宽度是说明栏加宽后重算的；`面板内滚` 那一列是加宽前实测的 —— 两张表各窄了 15px，
折行可能多一两行，重测一次再回来对。`lg` / `xl`（1280 / 1400 / 1426）三行不受影响。

阈值 `@md` = `28rem` = 448px 面板宽（约 **视口 1424px** 起），不是「够放就行」：
三列表格（退货率 / 保本 ROAS / 净利润）加间距最少约 370px，
448px 面板减掉 `p-4` 与 16px 栏距后每张 200px，留了余量。

**这里必须用容器查询，不能用 `xl:` / `2xl:` 视口断点**：视口 1535 → 1536 时左列从 `20rem` 跳到 `24rem`，
右列反而**变窄**（559 → 464px），按视口写的断点会在跨 2xl 那一下把表格挤扁。
反过来，行高是视口的、列数是容器的 —— 两者不同步，1424px 上下那一行会「多出」一截余量。

**滚动落在面板自己身上**，三栏各自滚、互不带动。中栏与右列的行高都**写死 `fr` 系数**：
面板内的滚动区必须有一个确定的高度才知道往哪滚，让它跟着内容长就会长到内容那么高、
滚动跑到外层去，最后里外两层（或干脆一层都不）在滚。想让某一块多留些高度，
把对应那一行的系数调大即可，例如把 `lg` 那档的第一行改成 `minmax(0,2fr)`。

投入与成本里的字段网格（`FIELD_GRID` 常量）跟着**左列的实际宽度**升降档，而不是跟着视口：
`sm` 2 列 → `md` 3 列 → **`lg` 回退 2 列** → **`xl` 再回退 1 列** → `2xl` 2 列。
两处回退都是因为**面板宽度不随视口单调递增**：`lg` 三栏生效、`xl` 中栏再分两列，都是变窄的档。
一格能放下「退货能收回的货款（%）」这类 11 字标签（12px 字号约 132px）就够，150px 上下排两列没问题。

> 这里用的是**视口断点**，而敏感性用的是容器查询 —— 不是随手选的：左列的宽度随视口**单调**变化
> （`lg` 中栏满宽 → `xl` 20rem → `2xl` 24rem），一组视口断点对得上；右列不是
> （`2xl` 那一下左列变宽、右列反而变窄），就非得看容器自己的宽度不可。

推算出来的客单价 / 单件毛利放在投入与成本面板的**底栏**（truncate），不放标题行：
这一列只有 `20rem` 宽，标题行是 `h-12` 固定高 + `flex-wrap`，提示稍长就会换行后被裁掉。

（改版式时有一条容易踩的坑，见 `## 踩过的坑`。）

窄屏按「预设 → 投入与成本 → 结果 → 敏感性 → 说明」顺序堆叠，预设与说明各自封顶；
结果与敏感性的滚动只从 `lg` 起（移动端 `max-lg:max-h-[60vh]`），表单面板移动端不封顶、随页面长。

表单里每个分组（`ui/InputSection.svelte`：成交与广告 / 成本项 / 退货 / 商品 / 平台）在 `lg` 以下
各带一个「收起 / 展开」—— 手机上一路滚十几个字段太长，收起来能少滚一半。收起走 `max-lg:hidden`
而不是 `{#if}`：字段始终在 DOM 里，首屏 HTML 与表单语义不能因为折叠而少一半；`lg` 起按钮自己隐藏。

**说明栏在移动端默认收起**（标题行右侧一个 `lg:hidden` 的展开按钮）：它排在最末，
要滚过参数与两张表才看得到，而它是「想核对口径时才看」的东西 —— 该给参数与结果让路。
用 `max-lg:hidden` 而不是 `{#if}`：正文始终在 DOM 里，首屏 HTML 的公式与口径是 SEO 长尾词的来源，
不能被折叠掉。

## 实现口径

- 结果卡按「你会问什么」拆成五件（`ui/ResultVerdict` / `ResultTrial` / `ResultUnit` /
  `ResultBreakdown` / `ResultRatio`），`ui/ResultPanel.svelte` 只留面板外壳、复制按钮与
  空 / 报错两种异常态 —— 每段的派生值与它渲染的那几行放在一起。
  ② 段是唯一按口径分成两个组件的：整盘走 `ResultTrial`、单件走 `ResultUnit`（两块：定价反推 + 规模试算）
- 单件口径**没有另写一套公式**：`parseUnitInputs` 把它换算成「订单数 = 1」的等价整盘输入，指标与敏感性表全部复用
- 敏感性表两张，**DOM 顺序 = 显示顺序**（上下排时是上下、并排时是左右，不用 CSS `order`）：
  ROAS 档位（整盘 1…10 共 10 档、单件围着保本线现算 10 档）→ 净利润在前、
  退货率档位（0…90% 共 10 档）→ 保本 ROAS 在后，各配一条 `ui/Sparkline.svelte` 的迷你折线；
  两张表**面板宽 ≥ 448px 时左右并排**（容器查询 `@md:grid-cols-2`），否则上下排
- 中栏的**栅格放置由每块自己声明**：`InputPanel` 的 `xl:row-span-2`（占满左列）、
  `SensitivityPanel` 的 `@container`（列数跟面板宽度走）—— `Converter.svelte` 只给列定义与行高系数，
  改归属时不用动 Converter 的 children 顺序
- 「最敏感的一项」扫 **9** 个经营变量（成交额是规模不是效率，不参与比拼；退款三类各自单列 ——
  能动的方向不一样，合成一个「退货率」报出来的那一条没法照着做），值为 0 的变量按 +5 个百分点 / +5 元试；
  一项都改善不了时返回 `null`，不硬凑答案
- 说明里的数字全部由两份示例现算（讲整盘用 `EXAMPLE_INPUTS`、讲单件用 `UNIT_EXAMPLE_INPUTS`），
  不写死，改示例不会让说明失真 —— 单件那几个数取自单件自己的示例，不是整盘的数 ÷ 100
  （两组示例的成本率填法不同，除出来的每件利润会跟单件结果卡差几分钱）
- 预设面板的版式与交互在 `$lib/components/PresetPanel`（与 HTTP 请求调试共用一件），
  `ui/PresetPanel.svelte` 只做业务绑定；两者的版式常量（`PRESET_ROW` / `PRESET_BADGE` 等）在 `$lib/ui/styles.ts`。
  CSV 下拉通过面板新加的 `extraActions` 槽挂进标题行右侧 —— **给了它，JSON 那两个按钮就收成图标、条数也让位**：
  这一栏只有 16rem（内容区 224px），带宽文字的导出 / 导入（各 58px）已经把 122px 占满，
  第三组控件放不下（收成图标后：标题 56 + 图标钮 30×2 + CSV 下拉 60 + 间隙 20 = 196px）。
  **挂了浮层就得同时传 `clip={false}`**：面板根节点是 `overflow-hidden`（裁圆角用的），
  菜单超出面板的那半截会被整块裁掉 —— 移动端这个面板只有 224px 高（`max-lg:max-h-56`），
  四项菜单 213px 一展开就少了最后一项（实测被切 44px）。这种裁切 axe 查不出来，只能肉眼看。

几处**边界状态的处理**（都是踩过的）：

| 情况                         | 处理                                                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 参数还空着                   | 结果卡走空态提示；**复制按钮禁用**（空串按 0 解析，metrics 不是 null）                                                    |
| 某项填了非法值               | 结果卡与敏感性卡都显示那句中文错误，敏感性卡不再渲染空表                                                                  |
| 成本按金额填、客单价还没到   | 明说「客单价就是成交额 ÷ 订单数」，要求先把这两项填好（按客单价填订单数时改说「成交额与客单价」），不按 0 硬算            |
| 订单数按客单价填、客单价是 0 | 只说「客单价要大于 0」（0 会除出 Infinity）；**留空不算错** —— 那是「还没填」，按 0 单走空态                              |
| 广告按 ROAS 填、成交额还没到 | 明说「按广告 ROAS 填广告时要先把成交额填好」—— `ROAS = 成交额 ÷ 广告费`，分子为 0 就解不出广告费，不按 0 硬算             |
| 当前退货率 / ROAS 超出档位   | **不高亮任何一行** —— 高亮端点会被误读成「我现在就是这一档」                                                              |
| 目标净利率填了非数字         | 输入框下方红字说明「按 0 算」，否则「填了 20% 却算出保本价」无从解释                                                      |
| 试算售价 / 销量填了非数字    | 红字说明「按当前售价 / 100 单算」—— 这两格留空就是「用默认值」，填错了才需要解释                                          |
| 规模试算的售价降到成本以下   | 照算（进价高过售价是真实状况），成本率会超过 100%、净利给负数，不拦                                                       |
| 反推出的成本上限被钳到 0     | 注脚改写「成本已无空间」，不显示一个读不懂的 `0.00`                                                                       |
| 广告费为 0（没投广告）       | **照常出结果**：① 右盒的净利润 = 贡献利润，不显示「—」；结论句改说「自然流量的账」。只有 ROAS 类的数还是「—」（分母为 0） |
| 老预设文件里没有 `adMode`    | 回落 `cost`（按花费），不因为少一个字段就整份拒收                                                                         |

## 踩过的坑

- **别把带面板的容器写成 flex 列 + `flex-1`**（改版式时容易踩）：`Panel` 根节点带 `overflow-hidden`，
  面板作为 flex 子项的自动最小尺寸会退化成 0（能被压到 0 高），而里面那层 `grid` 压不动 ——
  内容超出时 flex 会把高度整段从面板身上抽走，面板直接消失、还不出现滚动条。
  现在用定高栅格行 + 面板内部滚动，没有这个伸缩语义，也就没有这个问题。

## 已知取舍 / 暂不支持

**没算什么**：税、仓储租金、人工（可折进「其他固定成本」）、退货商品二次销售的降价、资金占用与账期。
结论是**经营判断的参考**，不是财务报表。

另外两类售后没有单独建模：**换货**（收入不减，但要付双程物流 + 商品降级）与
**不退货仅退款**（补寄 / 少件，收入部分退回、货却要不回来）。前者可以把双程运费折进「单均退货成本」，
后者可以按「未发货退款」记一笔，再把要不回的货值折进「其他固定成本」。

还有一处**已知的近似**：在途件的逆向运费实际低于签收回寄（拒收常由快递原件退回、有些平台由买家承担返程），
但「单均退货成本」只给了**一格**，两类统一按它算 —— 这会让成本**略微高估**。
方向与改动前一致、幅度小得多；要消掉它就得再加一格，与「在途是选填项」的轻量化意图冲突，所以先不做。
