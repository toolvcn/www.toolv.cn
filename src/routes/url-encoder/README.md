# URL 编解码 · /url-encoder

> 在线使用：<https://www.toolv.cn/url-encoder> ・ 数据全部本地处理，不上传、不落库

- **URL 编解码**：`encodeURIComponent`（严格，连 `:/?#` 都转义）与 `encodeURI`（整链，保留结构字符）两种策略；解码统一 `decodeURIComponent`，非法 `%` 报行列、坏字节原样保留不拖垮整批
- **参数表三段**：切到参数表视图把输入串拆成三段分别编辑 —— 地址（`?` 之前，含 `?`）/ 参数（`?` 与 `#` 之间的键值行）/ # 片段（`#` 之后的键值行）。参数行与片段行都可拖拽排序（手柄聚焦后 `↑ ↓` 也能移动），每段标题行右上角有添加按钮，任一段改动都实时合成回整条串
- **单屏一屏**：输入卡在「文本 / 参数表」两种视图间切换（同一张卡的标题行），输出卡随视图给出编解码结果或合成串；没有常驻标签栏，两套工作流共用同一副骨架
- **输出着色**：只给**内容**上色、结构分隔符（`://` `/` `?` `=` `&` `#`）中性灰 —— 域名（蓝）/ 路径段（绿）/ 查询的键与值（琥珀）/ 片段（紫）各一色。文本视图的输出（整串被组件编码过，如 `https%3A%2F%2F…`）也上色：先解码出结构、再把边界映回原串，进制大小写原样保留；只有真认不出的（如没填地址的裸查询串 `a=1&b=2`）整段不着色
- **面板全屏**：输入 / 输出卡片标题行各有一枚全屏按钮（原生全屏，Esc 退出）

## 参数在哪调

没有 `config.ts`，可调常量在 `core/types.ts`：

- `EXAMPLE_ENCODE_TEXT`：文本视图的首屏 / 示例（含中文、空格、`#` 片段等需转义字符）
- `EXAMPLE_QUERY_TEXT`：参数表视图的示例查询串（覆盖空格、中文、缺值裸键）
- 编码策略 `EncodeStrategy = 'component' | 'full'`、方向 `UrlDirection`、输入视图 `UrlInputView = 'text' | 'params'`、分段 `UrlSegment = 'query' | 'fragment'` 的类型定义也在 `core/types.ts`

## 档位

**L2**（+page.svelte + core/ 纯函数 + ui/ 面板）：`core/url.ts`（encodeText / decodeText / parseQueryString / composeQuery / composeFragmentParams / splitQueryInput / tokenizeUrl / firstBadPercent）+ `core/store.svelte.ts` + `core/types.ts`。

## 实现口径

- **输出上色走「分词 + `<span>`」**：`tokenizeUrl` 按结构切段（分隔符单独归 `delim`，不跟内容同色），渲染交给 `$lib/components/CodeView`（纯文本节点），不经过 `{@html}`；色板是工具内的 `URL_TOKEN_CLASS`
- **编码过的输出靠「解码切段 + 映回原串」上色**：逐 `%XX` 解出等价文本、切段后按码元边界切片原串（**不重编码**，所以混编与大小写都原样保留）；解不开或解不出结构就退回 plain
- **解码统一走 decodeURIComponent**：即便选了整链策略，解码也用 `decodeURIComponent`（`decodeURI` 会故意不解 `%2F` 这类，容易让人以为没解干净）
- **坏字节不拖垮整批**：解码失败时先 `firstBadPercent` 找第一个非法 `%` 编码给行列提示；单段查询参数解不开就 `tryDecode` 原样保留，不让一行坏数据毁掉整张表
- **查询段手写解析而非 URLSearchParams**：要「坏的值保持原样」、且连无等号的裸键也能进表；`&` 切分、空段忽略、无 `=` 的值记空串、`+` 与 `#` 一律按字面（空格按 `%20` 编码）
- **整条 URL 先拆段再编辑**：`splitQueryInput` 把输入拆成前缀（到 `?` 含）/ 查询段（`?` 之后、其后第一个 `#` 之前）/ 后缀（`#` 起），三段分别落在参数表的「地址 / 参数 / # 片段」，改完再拼回去。没有 `?` 时整串都当查询段，那时 `#` 只是字面字符、不当片段
- **两段都是「键 = 值」，编码与连接方式一致**：都用 `&` 连接、键值各自 `encodeURIComponent`（空格落为 `%20`），解析都用 `parseQueryString`。唯一差别是片段段**值为空时只输出键** —— `#结果` 这类锚点不该被补成 `#结果=`
- **两段的行都可拖拽排序**：走指针事件（HTML5 拖放在触屏上不触发），手柄聚焦后 `↑` / `↓` 与相邻那条交换（WCAG 2.2 的拖动替代）

## 合并后的口径

- **输入串是唯一事实来源**：文本视图直接编辑它；参数表视图把「地址 + `composeQuery(参数行)` + `#` + 片段行」写回它（单向，不循环）
- **切视图不写回**：进入参数表时按当前输入串重建表格，切回文本不合成 —— 只切一下视图不该改动内容
- **输出卡随视图给内容**：文本视图 = `transform(输入, 方向, 策略)`；参数表视图 = 三段合成出的整条串（带地址前缀时标题显示「结果 URL」，否则「合成结果」）
- **参数表视图不消费方向 / 策略**：那两组整组半透明 + `aria-disabled`，点击也不生效（要编解码就切回文本）

## 已知取舍 / 暂不支持

- 不做 URL 结构解析（拆协议 / 主机 / 路径）：三段分开编辑，但不解析也不校验地址段，改坏了不会提示
- 不做「按字段名排序」「去重键」「同键合并成数组」这类参数表整理（改表是所见即所得）
- 修复非法 `%` 编码不自动改输入，只提示位置，留给用户判断原来想写什么

## 验证过什么

- `core/url.test.ts`：两种编码策略的差异、解码失败的位置定位、`firstBadPercent` 各种坏 `%`、查询串解析（裸键 / 空段 / `?` 前缀 / `+` 与 `#` 按字面）、`splitQueryInput` 的 URL 拆段、`composeFragmentParams`（键值各自编码、值为空只留键、与查询串解析闭环）、`composeQuery` 的 `%20` 与过滤空行，以及 store 的三段拆解 / 拖拽与键盘改序后的合成结果 / 地址段可编辑 / 视图切换 / 复制目标
- 浏览器实测：输入视图切换、示例载入（随视图给不同示例）、粘完整 URL 进参数表改三段、拖拽与 `↑ ↓` 改行序、参数增删改实时合成、输出按 URL 结构着色、解码错误行列提示
