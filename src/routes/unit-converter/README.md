# 单位换算 · /unit-converter

> 在线使用：<https://www.toolv.cn/unit-converter> ・ 数据全部本地处理，不上传、不落库

- **十五类一页**：长度 / 面积 / 体积 / 重量 / 温度 / 速度 / 时间 / 角度 / 力 / 压力 / 功率 / 密度 / 能量 / 数据大小 / CSS 长度，各类各留各的输入与源单位，切换不丢状态
- **输入一次全出**：输入一个数值，该分类下所有单位实时换算成列表，源单位行标注「输入」原样回显，逐行可复制
- **线性两步走**：统一「源单位 → 基准 → 目标单位」。基准分别是米 / 平方米 / 升 / 千克 / 摄氏度 / 米每秒 / 秒 / 度 / 牛顿 / 帕斯卡 / 瓦特 / 千克每立方米 / 焦耳 / 字节 / px
- **温度仿射**：摄氏 / 华氏 / 开尔文按仿射对互转，不走线性因数
- **双口径与有歧义的单位都写清楚**：
  - 数据大小：KB / MB / GB（10³ 系）与 KiB / MiB / GiB（1024 系）并列，买硬盘、看内存各查各的
  - 体积：美制加仑（3.785411784 L）与英制加仑（4.54609 L）分开列，差 20% 不能混
  - 时间：月按 30 天、年按 365 天固定折算 —— 日历月要查表，不给一个假装精确的数
  - 速度：马赫按 15℃ 海平面声速 340.29 m/s 折算，随气温变，只作参考
  - 压力：mmHg 取常规定义值 133.322387415 Pa，与「1 atm = 101325 Pa」差 1.1e-4 —— 两个常规定义不可能同时满足「760 mmHg = 1 atm」，展示按 6 位有效数字仍是 760
- **CSS 长度跟随根字号**：px / rem / pt 互转，rem 的换算因数取页面里可改的根字号（默认 16，非法回退并标红）
- **结果最多 6 位有效数字**：去尾零去多余的点，`1e6` 这类整数不用科学计数展示
- **标签条能横滑**：十五个分类一行放不下，标签条整条横向滚动（按钮不窄过自己的文字）；宽度够时仍是均分整宽的老样子

## 参数在哪调

没有 `config.ts`，可调常量在 `core/types.ts` 与 `core/convert.ts`：

- `CATEGORY_LIST`：十五个分类及其单位表（线性单位记 `factor`、温度记仿射函数、CSS 的 `rem` 用占位 `factor`）
- `DEFAULT_INPUT` / `DEFAULT_FROM`：每个分类的首屏输入值与默认源单位（SSR 首屏即有换算结果）
- `DEFAULT_ROOT_FONT_SIZE = 16`：CSS 换算的默认根字号
- `formatNumber`：结果最多 6 位有效数字并去尾零；`parseAmount` 解析输入（空 / 非有限数返回 null）

## 档位

**L2**（+page.svelte + core/ 纯函数 + ui/ 面板）：`core/convert.ts`（toBase / fromBase / convert / formatNumber / parseAmount）+ `core/store.svelte.ts`（每类各存一份 `inputs` / `fromIds`，切分类不丢状态）+ `core/types.ts`。

## 实现口径

- **单位表是纯数据**：线性单位只记 `factor`（1 单位 = 多少基准单位），温度记一对仿射函数，rem 的 factor 是占位、运行时由根字号给（`factorOf`）
- **分类顺序按「几何 → 力学与热 → 数字」排**：长度 / 面积 / 体积挨着，力 / 压力 / 功率 / 密度 / 能量挨着，数据大小与 CSS 长度（IT 口径）压在最后 —— 十五个标签横滑时相邻的量纲容易找
- **每类各存一份输入与源单位**：切分类不丢状态；换算统一「源 → 基准 → 目标」两步，温度走仿射不经过 factor
- **结果格式化去掉伪装精确**：`toPrecision(6)` 后回串去尾零，`1e6` 这类整数不写成科学计数；`NaN` / `Infinity` 显示「—」

## 踩过的坑

- **单位表里的小数要写成算式**：eslint 的 `no-loss-of-precision` 会拦下位数超过 double 精度的小数 ——
  密度与英尺磅那两条就是写成算式（如 `0.45359237 / 0.028316846592`），顺带也说明了这个数是怎么来的。

## 已知取舍 / 暂不支持

- **不做货币与汇率**：那要联网取牌价，与「数据本地处理」冲突
- **不做自定义单位与自定义换算公式**：一页里放「用户自己填因数」的编辑器是另一个工具的量级
- **不做「英制市制」之外的冷门单位**（如英制蒲式耳、市斗）：收的都是日常与工程里真会遇到的
- 月 / 年按固定 30 / 365 天折算，不查日历（闰年、大小月不处理）

## 验证过什么

- 单测在 `core/convert.test.ts`（46 条，vitest 的 server project）：
  - 十五个分类各有锚点用例（1 英亩 = 4046.8564224 m²、1 节 = 1.852 km/h、1 atm = 101325 Pa、1 kWh = 3.6e6 J、1 kg/L = 1 g/cm³ …）
  - 温度仿射（100°C = 212°F、−40 交点）、数据大小的十进 / 二进两套口径不混算、CSS 的 rem 跟根字号走
  - **结构完整性**：分类 id 不重复、每个分类都有默认输入与默认源单位、默认源单位一定在自己表里、单位 id 不重复、每个单位都有 `factor` 或 `affine`
  - `formatNumber` 的 6 位有效数字与去尾零、`parseAmount` 的负数与科学计数
